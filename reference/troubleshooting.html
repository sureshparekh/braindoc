Troubleshooting#

What a message or a surprising result means, and what to do about it. For a problem with the installation itself, see Installation; for any run, brainsp check settings.yaml lists every problem with the settings at once, and brainsp selftest --quick checks the installation end to end.

The fit will not start#

No pixel can be fitted. Almost always the flag column: BRAIN reads 0 as a good pixel. A pipeline that writes 1 for good pixels must have its flag column inverted. Check too that the error column is positive: a pixel whose error is zero, negative or not a number is left out.

'wavelength_scale' is not set, and this fit needs it. The mode fits emission lines, so BRAIN must know whether the wavelengths are in air or in vacuum; it refuses to guess, because a wrong guess shifts every gas velocity by about 83 km s⁻¹ with nothing to show for it. SDSS, MaNGA, DESI and LAMOST are vacuum; MUSE and CALIFA are air.

nespop is refused with this library. The library does not reach the Lyman limit (911.76 Å), so it has no ionising photons to make a nebular continuum from; BasesGM is such a library. Use BC03, which ships with BRAIN, or another library that does (Template libraries).

The datacube fit says the redshift is missing. A cube’s redshift is required: give redshift= (0 for a cube already at rest), or a redshift column for every cube of the table.

A column of the targets table is refused. No enabled stage reads it; the message names the stages and the keys they take (Many datacubes).

The fit runs, but looks wrong#

The velocity is wrong, or the fit looks shifted. velocity_range must contain the galaxy’s velocity relative to the frame the spectrum is in. For a spectrum still at redshift \(z\), that is roughly \(cz\): the default range of −2000 to 5000 km s⁻¹ covers \(z \lesssim 0.017\). Remove the redshift (spectrum_in_rest_frame: false with spectrum_redshift) or widen the range.

The model is flat beyond some wavelength. The library does not reach that far: BasesGM covers 3540–6996 Å. BRAIN drops the pixels outside the templates’ coverage and says how many; narrow the range or use a library that reaches further.

Nearly every population weight is zero. That is correct. The non-negative solution is sparse, typically 5 to 20 templates of 84 carrying light, which is the honest answer of a degenerate problem. Report averages over templates, or raise smoothness for a smoother history.

\(\chi^2/N\) is far below 1. The errors are probably overestimated. The fitted values are unaffected, but the formal uncertainties, built from those errors and never narrowed below them, are too large by about \(1/\sqrt{\chi^2/N}\); the bootstrap’s follow the real scatter. Values of 0.65–0.75 are also what a spectrum resampled before reaching BRAIN gives, because resampling correlates the noise.

\(\chi^2/N\) is well above 1, and the formal errors are NaN. The templates do not fit the spectrum down to its noise. Above \(\chi^2/\mathrm{dof} = 2\) no formal error can describe the misfit, so BRAIN writes none; use error_samples for the bootstrap (Uncertainties).

sigma_star reads unknown, or r.sigma_star is None. The instrumental or the library resolution is unknown, so only the observed dispersion (vd_min, r.sigma) can be reported. Give instrumental_resolution, and library_resolution if the template files do not state theirs.

A value is written with < or >. It sat on a bound of its range: a limit, not a measurement. The comment under it says which bound.

A gas group reads unconstrained. None of its lines is detected at S/N 3, so its velocity and dispersion mean nothing, and its lines’ fluxes are upper limits.

Emission lines#

A line I expected is missing. BRAIN fits a line only where it can land on the fitted range at some velocity and dispersion inside gas_velocity_range and gas_dispersion_range; one that cannot is dropped and named in the log. A line under the mask or in a gap of the data is dropped and named too. Do not mask the lines you want fitted: the standard optical mask, made for spop, masks them all.

A line has a flux of exactly zero. It was fitted and the fit gave it no flux: a real non-detection, whose upper limit is 3 × its error.

\(A_V\) and the nebular continuum trade against each other. The fitted range starts redward of the Balmer jump (3646 Å), where the nebular continuum is nearly degenerate with dust; BRAIN warns. Extend the range below 3646 Å if the data allow it.

nespop fitted some spectra without the line tie (NC). Expected: the FC tie applies only where the gas is ionised by stars and the lines are reliable (The nebular emission). The log says how many got each treatment, and why.

Speed#

Every run recompiles. Something that changes array shapes differs between runs: the wavelength range, the template selection or the mode. Keep them fixed across a batch, and check that the compiled-code cache in ~/.cache/brain is writable.

A datacube on the CPU is slow. Check that cpu_workers is auto and that the log says the fit uses worker processes; on a shared server, other jobs compete for the cores. BRAIN never uses more than all but two of the cores it may run on (CPUs and GPUs).

The GPU is listed but not used, or --device gpu fails. JAX fixes its device at its first use in a process; choose it before the first fit, or start a new process.

The interface#

It will not start. No module named 'PySide6' means a different environment is running Python from the one BRAIN was installed into. On Linux, a missing xcb plugin needs sudo apt install libxcb-cursor0 libxkbcommon-x11-0. On a server without a display, use Python or the command line.

Dragging on a cube’s spectrum adds no mask region. Masks are in the rest frame, so the redshift must be entered first (step 2; 0 for a cube at rest).

A failed run. The interface appends the full message to brain_error.log in the output folder.

Still stuck#

Run the validator and the self-test, and open an issue at github.com/sureshparekh/brainv1/issues with their output and the log of the failing run.
