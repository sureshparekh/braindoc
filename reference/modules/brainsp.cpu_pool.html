brainsp.cpu_pool#

Worker processes for every stage of a datacube fit: on the CPU cores, or on several GPUs.

One process cannot use a many-core CPU for this problem (XLA’s threads speed up each spaxel’s linear algebra a little, and a batch waits for its slowest spaxel), so on a CPU the spaxels go to worker processes, each pinned to a core of its own (fit_megacube_jax.pinned_to), never more than every core but two (fit_megacube_jax.cpu_budget).

The pool sits behind the two functions every stage of the fit goes through, fast_cube.fit_queue_fast and fast_cube.run_rows: while a pool is installed (fast_cube.POOL), they split their spaxels into small chunks, the workers run the very same function on each chunk, and the results come back in the spaxels’ order. Spaxels are fitted independently, so the fit is the one a single process or a GPU gives, to rounding; the stars-alone kinematics, the main fit, the weak lines, the population and nebular fits and the errors all run on the workers.

Workers start once per cube fit and stay warm between the stages. Arrays a call shares between its chunks (the templates, the line tables, the nebular model) are sent to each worker once, by the hash of their contents, and kept there; only the chunk’s own rows travel with every call. A worker is python -m brainsp.pool_worker, never a re-run of the caller’s script.

On a machine with several GPUs a single cube is spread over them the same way (Pool(gpu_slots=…)): one worker per GPU, each running the queue with the lanes its card takes, while this process, on the CPU, only coordinates (the cube-wide decisions, the statistics, the megacube).

map(fn, calls) runs fn(*args, **kwargs) for every (args, kwargs) in calls on whichever worker is free, and returns the results in order. fn is a module-level function, sent by name. Thread-safe: the nebular fit runs its bins from several threads at once, and their chunks share the workers.
