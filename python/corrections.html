Corrections before the fit#

Two things happen to a galaxy’s light on its way to us that BRAIN undoes before fitting: the redshift, and the reddening by the Milky Way’s dust. The galaxy’s own dust is not a correction; it is fitted.

For one spectrum#

Setting

Default

Meaning

spectrum_redshift

0

the redshift that was, or is to be, removed

spectrum_in_rest_frame

True

True: the spectrum is already in the rest frame, and spectrum_redshift records what you removed. False: it is in the observed frame, and BRAIN removes spectrum_redshift itself

galactic_ebv

0

the Milky Way’s \(E(B-V)\) along the line of sight

galactic_rv

3.1

the Milky Way’s \(R_V\)

galactic_law

"CCM"

the Milky Way’s extinction law

 
# a spectrum still in the observed frame, at z = 0.031, behind E(B-V) = 0.04
r = brainsp.fit_spectrum("galaxy.spec", spectrum_in_rest_frame=False,
                         spectrum_redshift=0.031, galactic_ebv=0.04)

BRAIN applies them in this order:

  1. Galactic reddening, at the observed wavelengths \(\lambda_{\rm obs} = \lambda_{\rm rest}(1+z)\): the flux and its error are multiplied by \(10^{0.4\,A_\lambda}\), with \(A_\lambda = R_V\,E(B-V)\,q(\lambda)\) and \(q(\lambda) = A_\lambda/A_V\) the shape of the chosen law.

  2. The redshift, if spectrum_in_rest_frame is False: the wavelengths are divided by \(1+z\). The flux density is not rescaled.

Give the redshift even for a spectrum you de-redshifted yourself. The instrument smeared the light at its observed wavelength, so BRAIN needs \(z\) to find the instrumental resolution at each rest wavelength, and the Galactic dust acts at the observed wavelength too.

For many spectra: a corrections table#

A CSV file with a header row, the spectrum’s file name in the first column (relative to the table’s folder), then any of these columns:

Column (or alias)

Setting

Note

redshift (z)

spectrum_redshift

a redshift in the table is removed by BRAIN

rest_frame

spectrum_in_rest_frame

true if the spectrum is already at rest; false by default when a redshift is given

ebv (e(b-v))

galactic_ebv

rv (r_v)

galactic_rv

law

galactic_law

Empty cells keep the defaults.

filename,redshift,ebv,rv,law
galaxy_a.spec,0.031,0.04,3.1,CCM
galaxy_b.spec,0.0,0.0,,

table = brainsp.read_corrections_table("corrections.csv")
# {'/data/galaxy_a.spec': {'spectrum_redshift': 0.031, 'galactic_ebv': 0.04, ...}, ...}
results = brainsp.fit_spectra(None, corrections="corrections.csv")

brainsp.read_corrections_table() returns a dictionary {absolute spectrum path: {setting: value}}, which fit_spectra() accepts as corrections in place of the file. The same table works in the interface (Load table…) and on the command line (--corrections).

For datacubes#

A datacube’s corrections are keywords of CubePipeline: redshift, galactic_ebv, galactic_rv and galactic_law (Fitting a datacube). For several cubes, a per_cube table gives each its own (Many datacubes).

On your own arrays#

brainsp.corrections exposes the same operations for arrays you manage yourself:

from brainsp import corrections
factor = corrections.galactic_factor(wavelength_observed, ebv=0.04, rv=3.1, law="CCM")
flux_corrected = flux * factor
