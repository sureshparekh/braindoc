PythonThe library

Settings#

Every choice BRAIN makes is a setting with a name and a default: 83 of them, from the fitting mode to the solver’s tolerance. The same names are used in Python, in settings files, on the command line and, for the common ones, behind the controls of the interface. Settings lists every one.

The Settings object#

brainsp.Settings is a dictionary of every setting, with its defaults filled in:

import brainsp

s = brainsp.Settings(nebular_mode="espop", wavelength_scale="vacuum")
s["dust_range"]             # [-1.0, 5.0]
s.dust_range                # the same: keys are attributes too
s.ages = [1e8, 1e9, 1e10]   # change one
s.changed()                 # what differs from the defaults

{'ages': [100000000.0, 1000000000.0, 10000000000.0], 'wavelength_scale': 'vacuum', 'nebular_mode': 'espop'}

An unknown name is refused, with the nearest valid name suggested, so a typing error never silently leaves a setting at its default:

s["dust_rang"] = [0, 3]
# KeyError: "'dust_rang' is not a BRAIN setting; did you mean 'dust_range'? brainsp.Settings.names() lists them all."

Give it to a fit#

Every fitting function takes settings in three equivalent forms, and any setting as a keyword. A keyword overrides the same setting in the settings it is given:

r = brainsp.fit_spectrum("galaxy.spec", s)                           # a Settings
r = brainsp.fit_spectrum("galaxy.spec", "my_settings.yaml")          # a file
r = brainsp.fit_spectrum("galaxy.spec", s, dust_range=[-1, 3])       # s, then a keyword

Save it, and read it back#

s.save("my_settings.yaml")                 # every setting, as YAML
s2 = brainsp.Settings("my_settings.yaml")
s2 == s                                    # True

The file is plain YAML, one setting per line, and the command line reads it with --settings. brainsp init settings.yaml writes a copy of every setting with its full documentation as comments, to edit by hand.

Check it before fitting#

s.validate()                 # a spectrum's fit
s.validate(for_cube=True)    # a datacube's fit

validate checks the settings as a run would, without running, and raises an error that lists every problem found at once, each with what to do about it. The command line’s brainsp check settings.yaml does the same.

Find out what a setting does#

print(brainsp.Settings.describe("wavelength_scale"))
brainsp.Settings.names()           # every name, in the order of the settings file

describe() without a name describes every setting. The same text is on Settings and behind brainsp settings NAME.

Settings for datacubes#

A datacube’s fit reads the same settings for its physics. What concerns the cube itself (its extensions, the redshift, the pre-fitting stages, the S/N masks) is given to CubePipeline as keywords instead (Fitting a datacube), because a campaign of several cubes can give each cube its own value.
