The Python library#

import brainsp gives you everything BRAIN does: every fit, every pre-fitting step, every result and every figure, as Python functions and objects. The interface and the command line are built on the same functions, so whatever they do, code can do, and code can reach the settings they do not show.

The library at a glance#

import brainsp

s = brainsp.Settings(nebular_mode="espop", wavelength_scale="vacuum")   # settings
r = brainsp.fit_spectrum("galaxy.spec", s)                             # one spectrum
rs = brainsp.fit_spectra("spectra/*.spec", s, corrections="z.csv")     # many
cube = brainsp.fit_cube("manga.fits", redshift=0.024, settings=s)     # a datacube
brainsp.plots.map(cube, "Mage_L", "age.pdf")                           # a figure

To learn the library by running it, the tutorials come as short scripts with a comment on each step: brain_tutorials.zip (Tutorials).

Conventions#

  • Settings by name, anywhere. Every function that fits takes a Settings (or a dictionary, or a YAML file) and any setting as a keyword: fit_spectrum("g.spec", s, dust_range=[-1, 3]). A keyword overrides the same setting in s.

  • Units. Wavelengths in Å, velocities in km s⁻¹, extinctions in magnitudes, ages in years, metallicities as mass fractions (0.019 is solar for BasesGM). Fluxes are in the units of your data unless a name says otherwise.

  • Files are the record. Every fit writes its files before it returns, and every result object reads them back, so a result can always be reopened later with read_result or read_megacube.

  • Refusal, not guesswork. Where an answer cannot be inferred safely (the wavelength scale, a library that cannot run the mode you ask for), BRAIN stops with a message that says what to set, rather than guessing.

  • The device is chosen once per process. JAX fixes its device at its first use, so choose it before the first fit (CPUs and GPUs).

  • Logging. Progress is logged through Python’s logging; quiet=True on the fitting functions keeps only warnings.
