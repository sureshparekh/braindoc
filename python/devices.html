CPUs and GPUs#

BRAIN fits on the CPU or on NVIDIA GPUs, and sizes itself to the machine it finds: how many cores it may use, how many GPUs there are and how large they are. The device changes how long a fit takes, never its result: a fit on the CPU and the same fit on a GPU agree to rounding (10⁻⁵ at most, measured on every product of the three modes).

Choose the device#

Value

Meaning

"auto" (default)

a GPU when JAX can see one, the CPU otherwise

"cpu"

the CPU

"gpu"

an NVIDIA GPU; an error if there is none

 
import brainsp
brainsp.set_device("cpu")                      # before the first fit of the session
r = brainsp.fit_spectrum("galaxy.spec", device="gpu")   # or on the first fit itself

JAX fixes its device the first time it is used in a process, so only the first fit of a Python session can choose; set_device raises an error if JAX already runs on another device. JAX_PLATFORMS=cpu in the environment is respected by "auto". The interface starts every fit in a fresh process, so its device menu always takes effect. On the command line, --device does the same.

The machine, as BRAIN sees it#

Every fit’s log starts with what BRAIN found and what it will use:

Machine: 64 CPU threads on 32 cores available, 62 usable (all but two), 110 GB memory free
GPU: NVIDIA GeForce RTX 3060, 28 SMs, reduced-rate FP64; 64 lanes

On a CPU#

A single process cannot use a many-core CPU well for this problem, so BRAIN starts worker processes, each pinned to a core of its own, and every stage of the fit hands them its spectra or spaxels in small chunks as they come free: the stellar kinematics, the main fit, the weak lines, the population and nebular fits, and the uncertainties. The workers start once per run and stay warm from one datacube to the next.

cpu_workers

Workers

"auto" (default)

one per physical core, within the core budget; no more than the free memory allows (about 1.2 GB each) and no more than the work

a number

that many, never more than the core budget

1

no workers: everything in one process

The core budget is every core the process may use, minus two. BRAIN never uses more, so the machine stays responsive during a long run. “The cores the process may use” is what the operating system allows it (a SLURM allocation, taskset, a container’s limit), not every core of the node. BRAIN enforces the budget through the processor affinity of its processes, which also holds JAX’s own threads to it.

Hyperthreads are left out by default: on a 180-spaxel mock cube, 30 workers on 30 physical cores fitted it in 120 s and 60 workers on their hyperthreads in 133 s.

On a GPU#

On a GPU the spaxels go through a work queue: a fixed number of lanes, each holding one spaxel, and a spaxel that has converged leaves its lane to the next. The number of lanes is sized from the card itself:

Lanes

the rule

about two per streaming multiprocessor (SM), a power of two, as many as the card’s memory holds

RTX 3060 (28 SMs, 12 GB)

64 (measured: 32 lanes 4.8 spaxels s⁻¹, 64 lanes 5.2, 128 lanes 4.8)

RTX 5070 (48 SMs)

128

H100 (132 SMs, 80 GB)

256

If the first compilation runs out of memory, the lanes are halved and it is retried. batch_size (Python, settings) or Batch size (interface) fixes the number instead.

BRAIN computes in double precision throughout, because the linear algebra of the fit is too ill-conditioned for single precision (condition numbers near 10¹⁰). Consumer GeForce cards run double precision at 1/32 to 1/64 of their single-precision rate, while data-centre cards (A100, H100, B100) run it at half rate, so the second kind gains far more than its memory alone suggests. The log says which kind the card is.

Several GPUs, several cubes#

Situation

What BRAIN does

several cubes, several GPU slots

the cubes are dealt out to the slots, each a process of its own on one GPU, with its share of the card’s memory and of the CPU cores

one cube, several GPU slots

the cube’s spaxels are spread over one worker per slot; this process coordinates on the CPU

one ordinary GPU

one slot: the cubes run one after another, as always

Slots default to one per GPU, two on a card of 40 GB or more; gpu_slots= on run() and fit_cube(), or --gpu-slots on the command line, sets them (Many datacubes). Megacubes from several slots are bit for bit those of a sequential run; one cube spread over GPUs agrees with the single-GPU fit to 5 × 10⁻⁵.

Many spectra. fit_spectra() fits the spectra that share settings, wavelengths and usable pixels as one cube, which keeps a GPU’s lanes full: six mock spectra took 16 s instead of 65 s on the RTX 3060 (Fitting many spectra).

Compilation and caches#

JAX compiles the fit the first time it meets a problem of a given size (pixels, templates, lines, mode), which takes seconds. The compiled code is cached on disk (~/.cache/brain/jax; BRAIN_CACHE_DIR moves it) and later runs load it in about half a second; the resampled templates are cached too. Keep the fitting range, the templates and the mode the same across a batch, and only the first fit pays. brainsp clear-cache empties both caches.
