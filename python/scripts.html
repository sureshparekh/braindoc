A run as one file#

A run of BRAIN can be written as a single Python file that holds every setting, the mask and the data it fits. The file runs anywhere brainsp is installed, so it is the way to repeat a fit, to keep a record of it, to move it to a server, and to change a setting the interface does not show.

Write one#

import brainsp

# spectra, each optionally with its own settings
brainsp.write_script("run_spectra.py",
                     settings=brainsp.Settings(nebular_mode="espop", wavelength_scale="vacuum"),
                     spectra=["a.spec", ("b.spec", {"spectrum_redshift": 0.031,
                                                    "spectrum_in_rest_frame": False})])

# datacubes: give CubePipeline's keywords, or a pipeline
brainsp.write_script("run_cube.py", kind="cube", cubes=["cube.fits"], redshift=0.02,
                     sn_mask=[3], fit_sn_threshold=3, wavelength_scale="vacuum")

p = brainsp.CubePipeline("cube.fits", redshift=0.02)
p.export_script("run_cube.py")

write_script(path, kind="spectrum", settings=None, spectra=(), pipeline=None, device="auto", **pipeline_options) returns the path written. In the interface, Export run script… does the same (Exporting maps and runs); on the command line, brainsp init run.py SPECTRA... writes a spectrum script and brainsp cube ... --export run_cube.py a datacube one.

What is in it#

The file is ordinary Python, meant to be read and edited:

Block

Holds

SETTINGS

every setting, one per line, with its value

MASK

the wavelength mask regions, if any

SPECTRA or PIPELINE

the spectra with their own corrections, or the cubes and every stage of the pipeline

DEVICE, OUTPUT_DIR

where to fit, and where the results go

main()

the run itself, through the public brainsp functions

Run it#

python run_spectra.py                     # fit everything it lists
python run_spectra.py other.spec          # or other spectra, with its settings
python run_spectra.py --device gpu
python run_cube.py --check                # validate the pipeline, fit nothing

Paths that travel#

Paths inside the folder the script is saved in are written relative to the script, so the folder can be copied to another machine, with the data in it, and run there as it is. Paths outside it stay absolute, and the interface lists them when it exports, because they will not travel with the folder. Save the script in the folder that holds your data.

Change a setting#

Open the file, change the value in its SETTINGS block, and run it again. Every setting is there, including those the interface does not show, each under the name Settings documents.
