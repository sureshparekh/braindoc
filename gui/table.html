Fitting a table of spectra#

The Spectrum workspace can fit a whole table of spectra in one go, each with its own redshift and Galactic reddening, and the same model for all.

The table#

A table is a CSV file, one spectrum per row. The first column is the file name, relative to the table’s own folder; the others are optional and can come in any order:

Column

Meaning

Default

filename

the spectrum file

(required)

redshift

the redshift to remove

0

rest_frame

true if the spectrum is already in the rest frame

false when a redshift is given

ebv

the Galactic \(E(B-V)\)

0

rv

the Galactic \(R_V\)

3.1

law

the Galactic extinction law

CCM

 
filename,redshift,ebv,rv,law
mock_old_population.spec,0.0,0.0,3.1,CCM
mock_observed_frame.spec,0.03,0.05,3.1,CCM

A redshift in the table is one BRAIN removes: each spectrum is taken to be in the observed frame unless its rest_frame column says true. The mock data written by brainsp examples include such a table, spectra/corrections.csv.

Fit it#

  1. Load the table

    In step 1 Spectrum, press Load table… and choose the CSV. The caption beside the button says how many spectra it found, and names any file it could not.

  2. Check a spectrum

    Click any spectrum of the table in the list: step 2 Corrections is set from its row, so you can see what will be removed before the fit.

  3. Set the model once

    Choose the model in step 4 Model. It applies to every spectrum of the table.

  4. Fit them all

    In step 5 Fit, press Fit every spectrum in the table. Each result is drawn as it arrives, and the status line reports the progress.

How the table is fitted#

Spectra that the fit would treat identically (the same settings, the same wavelengths once corrected, and the same usable pixels) are fitted together, as one cube of many spectra; on a GPU this keeps every lane of the device busy instead of one. The others are fitted one at a time, and on a CPU they are spread over worker processes, one per physical core, never more than all but two cores. Every spectrum gets the result it would get fitted alone (Fitting many spectra).

Each spectrum writes its own files to brain_out, named after the spectrum (What a fit writes). Export run script… in step 5 writes the whole table, with its corrections, as one Python file (Exporting maps and runs).
