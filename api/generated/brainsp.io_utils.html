brainsp.io_utils#

NewBrain I/O Utilities Loading spectra, SSP libraries, masks, and writing output.

Everything here is file handling and numpy except the resampling of a template onto the fitted grid, which is spectral_engine and therefore JAX. That import is made inside the two functions that resample, so that asking this module what a library covers, or what a spectrum contains, does not start a JAX backend. The desktop interface asks both of those questions before a device has been chosen, and a backend started in the process that asks is a backend the fit can no longer choose.

brainsp.io_utils.library_coverage(ssp_folder, bases_info)[source]#

What a template library covers, measured from its own files.

Whether a library can support the nebular modes is arithmetic rather than preference. Q(H) is integrated from the raw spectra shortward of the Lyman limit, so a library whose files begin redward of it emits, by construction, no ionising photons at all, and its nebular continuum would be identically zero while the fit ran to completion and looked converged. A hardcoded list of which libraries qualify goes stale the first time one is regenerated or a variant is shipped, so the question is asked of the files.

Only the first and last wavelength of each file are read, which is cheap enough to run before a fit rather than partway through one.

Only the nebular modes are affected. spop and espop fit the emission lines from the catalogue with free amplitudes and predict nothing, so they need no ionising photon budget and are available for every library.

Returns a dict with the bluest and reddest wavelength across the library, how many of its files reach below the Lyman limit, and the modes that are therefore available for it.

brainsp.io_utils.load_native_template(path)[source]#

Read one template file at the sampling the library wrote it on.

Nothing is resampled, normalised or trimmed. This is the form a line-spread-function correction has to see: the kernel that separates two line-spread functions is a width in Angstrom on the grid the library was tabulated on, and a template that has already been mapped onto the fitted log-lambda grid no longer has that grid to be convolved on.

Returns:
wavelength1D array

The template’s own wavelength axis, in Angstrom.

flux1D array

The template’s own flux density, in the library’s own units.

brainsp.io_utils.resample_template(ssp_wl, ssp_fl, target_wl)[source]#

Map one template onto the fitted grid, conserving flux.

Target pixels outside the template’s own span stay at exactly zero, which is the signal the coverage test downstream reads to decide which pixels no template reaches. Because the span is a property of the file and not of anything done to its flux, a template convolved before this step covers exactly the pixels it covered before.

brainsp.io_utils.read_mask_regions(mask_file)[source]#

The regions of a wavelength mask file, as [(start, end, weight, label)].

Two layouts are read:

  • The .sm / .gm layout (BRAIN’s own when it saves one): a first

line holding the number of regions N, then N lines of

    start  end  weight  [label ...]

Exactly N lines are regions. Whatever follows is free text, and
published mask files use it: the standard SDSS emission-line mask ends with an *example* that gives Ca II K and the
G band twice the weight. Reading every numeric line, as this function
once did, applied that example and up-weighted both windows in every
fit that used the file.

  • A plain list, with no count: every line that starts with two numbers

is a region. Lines starting with '#' are comments in both layouts.

The weight is optional and defaults to 0 (the region is excluded). A third field that is not a number is the start of the label, and the region is excluded as usual.

Returns (regions, n_skipped): n_skipped counts lines that should have been regions and did not start with two numbers.

brainsp.io_utils.stellar_component_flags(bases_info, names)[source]#

Which of the loaded templates are stellar populations, said by the library.

The template catalogue’s KIND column is the declared answer: ‘ssp’ for a stellar population and something else – ‘powerlaw’ – for a component that is not one. brain_settings.read_catalogue carries that word onto every entry, and this reads it back. Nothing here looks at a filename, a short name, an age or the shape of a spectrum, because all four are conventions a new library is free to break, and breaking them would move a mass silently.

The lookup is by filename rather than by position: load_ssp_templates skips an entry whose file is missing, so the loaded arrays can be shorter than bases_info and a positional flag would then be attached to the wrong component. A name that no entry describes is a programming error and is raised rather than assumed stellar.

Libraries loaded through load_bases_dir or scan_ssp_folder carry no KIND at all; those formats cannot express a non-stellar component, so every entry is a stellar population and the flags come back all True.

brainsp.io_utils.population_statistics(weights_star, norm_factor, av, yav, ssp_yav_flags, ssp_mstars, ssp_fbase_norms, k_norm, is_stellar)[source]#

The per-template light and mass quantities, for one spectrum or a batch.

x_j, Mini_j and Mcor_j are what every population product is built from – the summary file’s percentage columns, and every population map of a megacube. They are computed here, once, so that a map value and that spaxel’s summary line cannot disagree: they are the same arithmetic on the same weights rather than two implementations of the same formula.

A weight is the contribution of a template to the reddened spectrum at the normalisation wavelength. Turning it into a mass means undoing the extinction that template suffered – A_V plus YAV for the templates flagged as young – and dividing by the library’s flux per unit initial mass at that wavelength, which is what ssp_fbase_norms holds. Leaving the extinction out makes the dustiest populations look lighter than they are, and the error grows with A_V, so it does not show up as an offset.

is_stellar says, per template, whether that division means anything. A featureless power law is not a stellar population: it has no stars, no surviving stellar fraction and no mass, and its fbase_norm is the flux of an arbitrarily scaled file rather than a flux per solar mass. Its Mini_j and Mcor_j are therefore exactly zero, it is out of Mini_tot and Mcor_tot, and its mass percentage columns read 0. The magnitude of what that removes is set by nothing physical: the same fit, with the same weights, reports whatever mass the power-law file’s normalisation happens to imply, so the error it fixes is unbounded rather than small.

Its LIGHT is untouched and stays in x_j, in light and in flux_tot. The power law genuinely does contribute light, and a component that is 30 per cent of the light and 0 per cent of the mass is the correct reading of an AGN continuum sitting on top of a stellar population. The two columns are normalised over different sets on purpose: x_j over every component, Mini_j and Mcor_j over the stellar ones, which is why a summary file can show a non-zero x_j against a zero Mcor_j without either being a bug.

The ionising photon budget is deliberately not touched here. Q(H)_total is built in brainv1 from the same expression, but what it multiplies is photons per unit of a template’s own normalisation, and a power law does ionise. Zeroing a mass is not a statement about photons.

The leading axis is optional. Pass a (n_ssp,) weight vector and every returned array is one-dimensional; pass (n_spec, n_ssp) and the totals come back as (n_spec,). That is how the batched cube path and the single spectrum share one implementation.

brainsp.io_utils.deviation_percent(flux_observed, model, fitted)[source]#

adev: the mean of abs(observed - model) / observed over the fitted pixels.

A deviation relative to the observed flux is undefined where that flux is not positive, so those pixels are left out of the mean and counted separately rather than being given an arbitrary value. They are still fitted and still counted in the chi-square; this is a reporting decision and not a change to what was minimised.

Works on one spectrum or on a batch: the last axis is wavelength.

brainsp.io_utils.effective_pixel_count(inv_sigma)[source]#

Nl_eff: the pixels of non-zero weight, the ones that entered the chi2.

A pixel is in the chi2 exactly when its inverse sigma is above zero, so this is the count the summary file divides by and the count the cube’s Nl_eff plane carries. Works on one spectrum or on a batch: the last axis is wavelength.

brainsp.io_utils.chi2_per_effective_pixel(chi2, n_eff)[source]#

chi2 divided by Nl_eff, which is the convention BRAIN reports.

The single-spectrum summary, the cube’s CHI2 extension and its PoPBins ChiSqrt plane all quote this one number, computed here so that they cannot drift apart: a reader comparing a spaxel of a cube against the same spectrum fitted on its own is comparing the same quantity. Nothing is subtracted for the free parameters – that is the other convention, and it is reported separately under its own name.

Nl_eff is floored at one so that a spectrum which somehow reached this point with no fitted pixel returns its raw chi2 instead of an infinity. Scalars and batches alike.

brainsp.io_utils.write_summary(filepath, config, params, weights, w_errors, n_star, ssp_short, ssp_ages, ssp_metals, ssp_names, ssp_yav_flags, ssp_mstars, ssp_fbase_norms, fit_stats, gas_names, chi2, n_pix, wl_range, runtime, n_fev, nebular_stats=None, lsf_report=None, gas_report=None)[source]#

Write the fit summary to a text file.

vd_min keeps its historical meaning and its exact value: the dispersion the kinematic kernel applied to the template library. Everything the instrument contributes to that number is reported separately, in the instrumental resolution block, so that no reader has to assume vd_min is astrophysical and no reader is left with a bare 0.00 to interpret.

The gas kinematics are written here too, per kinematic group, because until now they reached the log and nothing else: a summary file recording an espop fit stated the emission-line fluxes and said nothing about the velocity or the width they were fitted with. The two dispersions in this file follow DIFFERENT conventions and every line that carries one says which: sigma_star is INTRINSIC, the instrument taken out in quadrature, while sigma_gas and vd_min are OBSERVED, with the instrument still in them. See _write_gas_kinematics_block.

The emission-line block states the wavelength scale the lines were placed on, for the same reason every dispersion in this file states its convention: a flux table that does not say whether its rest wavelengths were air or vacuum is a table whose gas velocity is ambiguous by 83 km/s, and nothing else in the file would reveal it. The scale is a declaration about the observed spectrum, made in the settings file and copied here; it is not a measurement and not something BRAIN infers.

Mini_tot, Mcor_tot and Q(H)_total are apparent, not absolute. They are the observed flux normalisation divided by the library’s flux per solar mass, which is a mass only once the flux has been turned into a luminosity. No distance enters this code anywhere, so the missing factor is flux_unit * 4*pi*d^2 / L_sun and the reader has to supply it. These were previously labelled “(Msun)”, which was wrong by whatever that factor happens to be — about 3.5 dex for a MaNGA spaxel at 100 Mpc, and distance-dependent, so not even a fixed offset across a sample.

The factor carries no template index, so every fraction built from these numbers was and remains correct: the per-template percentage columns are bit-identical under a rescaling of the input flux. Only the absolute normalisation was ever mislabelled, which is why this is a change of wording and not of arithmetic.

x_j, Mini_j(%) and Mcor_j(%) are taken from fit_stats as they were computed, not rebuilt here from the weights and the totals. They were rebuilt here once, from the same formulae, and a second implementation of a formula is a second place for it to change: the whole point of population_statistics is that a megacube’s population map and this file’s column are one arithmetic. A power law reaches this table with a non-zero x_j and a Mini_j(%) and Mcor_j(%) of exactly zero, because it carries light and has no stars; see population_statistics.
