brainsp.fast_cube#

A faster batch fitter for datacubes, kept apart from the one in use.

fit_megacube_jax._fit_batch fits one batch of spaxels. This module offers a drop-in replacement, fit_batch_fast, with the same arguments and the same return values, and changes only how the work is done, not what is computed. It is a separate file so that it can be measured against the reference on the same spaxels before anything in the pipeline depends on it.

Three changes, each aimed at a cost measured on a real MaNGA batch:

  1. THE NNLS IS WARM-STARTED. Every forward evaluation solved the

non-negative least squares from an empty active set, rediscovering the
~16 templates with weight, one per sequential step. Between successive LM
iterations, and between the perturbed evaluations around one point, that
set barely moves. solver.solve_active_set accepts a starting set and is
documented, and tested, to reach the same vertex from any start: the
start changes the path, not the answer. Here the set is carried through
the LM loop, the clipping pass and the final evaluation. Measured on 16
spaxels: 23.6 ms cold, 2.7 ms warm, weights identical to 0.0.

  1. THE JACOBIAN IS ANALYTIC (VARIABLE PROJECTION). The LM differentiates

the projected residual  rho(theta) = b - A(theta) w*(theta), where w* is
the NNLS solution. The reference does it by central differences: 2 x 8
perturbed evaluations per iteration, each a full template build and a
full NNLS. On the active set P the NNLS solution is the least-squares
solution on the columns in P, so the derivative has a closed form
(Golub & Pereyra 1973, the full form, not Kaufman's approximation):

    d rho / d theta_k = -(I - Pi_P) (dA_k w)  -  A_P G^-1 [dA_k^T rho]_P

with G = A_P^T A_P and Pi_P = A_P G^-1 A_P^T. dA_k w and dA_k^T rho come
from one forward-mode pass of JAX through the model, and no NNLS is
solved at all. This is the derivative central differences approximate,
without their truncation error. It is exact while P is fixed, which is
what central differences also assume unless a step happens to move a
template in or out of P. It covers the unconstrained problem only; with
the simplex constraint there is an extra multiplier term, so a simplex
fit keeps central differences, warm-started.

  1. THE VELOCITY GRID RUNS AS A SCAN. The initial-velocity search evaluated

all 47 grid points at once with vmap, so a batch held 47 copies of the
template matrix per spaxel: that is what ran a 12 GB GPU out of memory at
32 spaxels and forced 16. The points are now visited in order with
lax.scan, which carries the active set from one velocity to the next as
well. The chi-squared at each point is the same number, so the argmin is
the same point.

Nothing here touches the physics: the model matrix is built by the same functions in the same order as optimizer._forward_full, the LM keeps the reference’s damping, acceptance and convergence rules line for line, and the clipping pass is the reference’s.

The stellar template matrix with its Fourier transform, computed once.

Broadening is a product in the Fourier domain, and the templates are the same for every spaxel and every evaluation: their transform was computed afresh each time, per spaxel. It is computed once per batch here, and an evaluation only multiplies by the kernel and transforms back. n_left and n_fft are the padding and transform length, fixed for the batch.

brainsp.fast_cube.outlier_nsigma(resid, istat, isig, scaled)[source]#

Each pixel’s residual in the units outliers are judged in.

scaled False (outlier_scale ‘error’, the default): its own error, as STARLIGHT’s NSIGMA clipping – a pixel beyond the threshold is clipped however badly the rest of the spectrum fits. scaled True (‘typical’): the larger of its error and the spectrum’s typical residual (1.4826 MAD of residual/error), so that where the model cannot match a very high-S/N spectrum anywhere the clip does not take most of the pixels.

brainsp.fast_cube.fit_batch_fast(flux_b, isig_b, istat_b, M_star, lam, velscale, dk, D_full, yav_flags, rest_wl, ratios, n_comp, gids, max_comp, n_groups, blo, bhi, v0_grid, av0, sig_s0, sig_g0, solver='active_set', simplex=False, max_iter=200, ftol=1e-07, xtol=1e-07, n_clip=0, clip_threshold=3.0, have_errors=True, analytic_jacobian=True, pad_pixels=None, clip_scaled=False)[source]#

fit_megacube_jax._fit_batch, faster. Same arguments, same return tuple: (params, weights, fitted, stellar, gas, chi2, n_eff, converged, n_iter, inverse_sigma) per spaxel.

analytic_jacobian=False keeps the reference’s central differences, still warm-started and with the scanned grid. It exists to separate the three changes when measuring them: with it, any difference from the reference is down to the warm start and the scan alone.

Only the active-set solver has an active set to carry. Any other solver is refused rather than quietly run through a path it was not measured on.

pad_pixels is the padding of the broadening transform at each end, a fixed number for the batch: the pipeline sets it from the fit’s own bounds (8 sigma_max + the largest velocity, plus a margin), which the kernel never reaches past. None pads by the full spectrum length, as spectral_engine does when it is not told the bounds: a transform three times as long, for a model the same to 1e-13 (to 2e-6 at the outermost pixels for a kernel under a pixel and a half, which rings).

fit_batch_fast for any number of spaxels, scheduled as a work queue.

Takes every spaxel at once (flux_all etc. are (n_spaxels, n_pix)) and returns fit_batch_fast’s tuple with n_spaxels rows. lanes spaxels are in flight at a time; each lane is advanced chunk LM iterations per step, and a lane whose spaxel is done is refilled from the queue, a quarter of the lanes at a time so the grid search runs in groups. progress(n_done, n_total, finished) is called as spaxels finish, with the indices (rows of flux_all) of the ones that just did.
