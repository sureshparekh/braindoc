brainsp.fit_megacube_jax#

BRAIN v1 — Pure JAX Datacube Fitter Fits all valid spaxels using jax.vmap batches. Runs on one device, GPU or CPU, chosen with –device; a batch of spaxels is one vmapped call on that device. Outputs a MEGACUBE-format FITS file.

One template matrix is shared by the whole cube, so the line-spread-function correction is applied to it once, after preprocessing and before the first batch is compiled: it costs nothing per spaxel and does not change any array shape, so nothing recompiles. lsf_decision_pixels says which pixels the decision is taken over.

The KINEMATICS plane for sigma_star is what the kernel applied to the library, an observed dispersion. When ‘instrumental_resolution’ is set, an LSFCORR extension carries the dispersion with the remaining difference in line-spread functions taken out in quadrature, the difference itself, and a per-spaxel flag saying whether that is a measurement, an upper limit, or not reportable. When it is not set, no LSFCORR extension is written and the file is what it has always been: there is no plane of corrected dispersions that is secretly a copy of the uncorrected one.

brainsp.fit_megacube_jax.select_device(device)[source]#

Put JAX on the device asked for, and refuse to go on if it is not there.

This module imports JAX at the top, so by the time the command line has been parsed JAX has already read JAX_PLATFORMS from the environment, and writing the variable then does nothing. That is what –device cpu used to do: it logged “CPU mode enabled” and fitted on the GPU. The platform is set through JAX’s own configuration instead, which is honoured as long as no device has been touched yet, and the backend that actually starts is compared with the request, as brain_child does for the desktop interface.

None means auto: whatever JAX picks, which is the GPU when one is visible.

brainsp.fit_megacube_jax.out_of_memory(exc)[source]#

Whether a failure is the device running out of memory, and not a fault.

XLA reports it as RESOURCE_EXHAUSTED from whichever kernel asked last, so the only thing that distinguishes it from a real error is the text. The test is deliberately narrow: anything it does not recognise is re-raised rather than retried at half the batch size, because retrying a genuine fault would turn one loud failure into a sequence of quiet ones.

How many CPU workers to start.

“auto”: every core but one (leaving the machine usable), no more than the memory available allows at WORKER_GB each, and no more than there are spaxels. An integer is taken as given (1 means no workers: the fit runs in this process).

brainsp.fit_megacube_jax.lsf_decision_pixels(matrix, inv_sigma_batch)[source]#

The pixels the line-spread-function decision is taken over, for a cube.

The whole cube is fitted with one template matrix, so the verdict on each group of templates — convolve it up to the data, or leave it at its native resolution — is reached once and binds every spaxel. A single spaxel’s mask is the wrong unit to reach it with: a convolution justified on one spaxel’s window would be forced onto spaxels that fit pixels where it is not.

Taken here as the union of the good pixels of the spaxels that will be fitted, intersected with the pixels at least one template covers. The union is the conservative member of the family: prepare_templates refuses a group when the library is broader than the data anywhere in the mask, so a wider mask can only turn a convolution into a refusal, and a refusal changes nothing about the fit and is reported. The intersection would license a convolution over a window narrower than any spaxel actually fits. The coverage mask alone would drag in pixels every spaxel has discarded.

The coverage term is not optional. Pixels beyond the reach of the library are identically zero in every template, and letting them into the decision binds it to wavelengths that carry no template flux at all.

brainsp.fit_megacube_jax.to_rest_frame(wl, cfg, logger)[source]#

Put an observed-frame cube onto rest wavelengths.

The two entry points take different frames, and that asymmetry is the kind of thing this code fails silently on, so it is stated here and in brain_setup.yaml rather than left implicit. The scalar path expects a spectrum you de-redshifted yourself; a datacube arrives straight from the telescope in the observed frame, so the cube paths do it before any spaxel is fitted.

Applied to the wavelength axis rather than to the flux, and before the log grid is built, so every template, mask and line window downstream is in one frame. Nothing is interpolated and no flux is touched.

cube_redshift and spectrum_redshift do opposite jobs and setting both is refused in brain_settings.validate, so reaching here with a non-zero value means exactly one correction is wanted.

brainsp.fit_megacube_jax.line_table_for(cfg, lam_grid, weight=None)[source]#

The emission-line design the cube path will fit, for this configuration.

Named and separate so the cube path’s answer to “which lines am I fitting” can be read without running a fit, and so it has one definition rather than being inlined where nothing can check it.

Gated on cfg.fit_emission_lines, as brainv1 gates it. to_config already forces that false whenever nebular_mode is spop, so the single flag carries the rule that spop mode is purely stellar and needs no second test for the mode here. Without the gate the cube fitted fourteen gas templates in off mode, where the scalar path fits none, so the two were fitting different models and no map from a cube was of the quantity the scalar path reports.

Returns the precompiled line table, the kinematic group labels in the order their fitted parameters are laid out, and the number of groups. With lines switched off the table is empty and the design matrix is stellar alone.

The order comes from emission_lines.group_positions, which is the same expression the table itself uses to turn a group label into a position in the parameter vector, so the bounds built from these labels and the kinematics each line reads cannot drift apart.

brainsp.fit_megacube_jax.quality_mask(data, name, logger=None)[source]#

A quality-mask cube as the integers its bits are tested on.

BRAIN reads a quality mask as MaNGA’s: a pixel is bad when bit 10 (DONOTUSE, 1024) is set. A mask written as floating point (a JWST cube’s MASK of 0.0 and 2.0) cannot be bit-tested, and the test raised a numpy TypeError mid-run. Whole-number floats are read as those integers, and a NaN entry as a bad pixel; anything else is refused with the reason. A mask whose non-zero values never carry bit 10 flags nothing, and the log says so rather than leave the user believing the mask was applied.

brainsp.fit_megacube_jax.preprocess_datacube(flux_cube, ivar_cube, mask_cube, wl_lin, lam_grid, norm_wl, has_err=True, file_weight_lin=None, spaxel_select=None, missing_error='exclude', logger=None)[source]#

Every valid spaxel’s flux and inverse sigma on the log grid, batched.

This follows brainv1 step for step, because a cube fitted here and a spectrum fitted there must give the same answer, and every step where the two differ is a place they silently do not.

The flux is moved onto the log grid by the same flux-conserving integral the scalar path uses, not by linear interpolation. The two are not approximations of each other: the integral redistributes flux between bins of unequal width, and on the reference spectrum the interpolated version was wrong by 18.9 per cent at its worst pixel.

That choice forces the rest. Once the rebin blends neighbouring input pixels, an output pixel next to a rejected one holds some of its flux, so the quality mask has to be carried by the same operator – the clean fraction – and not by a nearest-neighbour lookup alone. Both carriers are kept, as in brainv1: the nearest-neighbour weight says which input pixel an output pixel sits on, the clean fraction says how much of its value came from input worth keeping.

The error is filled only where the inverse variance carries no information, never where the mask rejects a pixel. Those are different questions and conflating them inflates the error at flagged pixels, which then bleeds into their neighbours through the interpolation and reaches pixels that were never in doubt.

The resampling is vmapped over spaxels rather than looped, since the two grids are shared and only the flux differs.

spaxel_select, when given, is a (n_y, n_x) boolean or integer plane and a spaxel is fitted only where it is true. That is how a signal-to-noise mask reaches the fit: SN_MASKS_<t> is 1 where the spaxel passed the threshold, so selection is intersected with the emptiness and quality tests here rather than replacing them – a spaxel above the threshold whose flux is entirely flagged is still not fittable, and quietly fitting it would produce exactly the plausible-looking answer this code has to avoid.

The per-pixel error on the log grid is returned alongside the inverse sigma, and is None when the cube carries no inverse variance. Outlier clipping needs it: its criterion is abs(resid) / err, while inv_sigma is sqrt(mask weight) / err, and the two agree only where the mask weight is exactly one. load_mask allows any non-negative weight, so a cube fitted with a weighted mask would otherwise clip at a different threshold from the same spectrum fitted on its own.

missing_error says what a pixel with a finite flux but no usable error is. “exclude” (the default) leaves it out: in MaNGA an inverse variance of zero marks a pixel not to be trusted. “interpolate” keeps it, with the error interpolated from the spaxel’s neighbouring errors, when the flux is finite and the quality mask does not flag it. Some cubes give no error for real data: the NIRSpec cubes of Riffel et al. carry NaN errors on 15 per cent of their pixels, and on 45 per cent at 2.20-2.27 um, where the flux scatters exactly as it does elsewhere. Leaving those out discards half the red end, where hot dust and A_V are told apart.

brainsp.fit_megacube_jax.spaxel_selection(hdu_list, hdu_flag, n_y, n_x, flux_cube=None, logger=None)[source]#

The per-spaxel selection plane a flag extension carries, or None.

Which value of a two-dimensional flag means “fit this spaxel” is not settled in the wild, and getting it backwards is silent and total: the fit runs on empty sky, every spaxel converges on noise, and the cube is full of numbers. Both conventions are found in published megacubes: “anything different from 0 is a bad spaxel” is documented, and SN_MASKS_<t> planes are written that way – measured on a real megacube, SN_MASKS_10 == 0 marks 145 spaxels of median S/N 13.6 and != 0 marks 5331 of median S/N 0.00 – while readers exist that do the opposite, skipping the spaxel when the flag is falsy.

So the polarity is measured rather than assumed. The convention that selects the spaxels carrying signal is the right one, and the decision is logged with the evidence that produced it. Without a flux cube to measure against, the documented convention is used and the log says it was assumed.

“Carrying signal” is most of the spectrum being positive, not any of it. On a sky-subtracted cube an empty spaxel is noise about zero, so its maximum is positive nearly always: measured on the raw FLUX extension of manga-8626-12704, “max > 0” calls 60.6% of the empty spaxels signal and leaves a 39-point margin, where requiring most wavelengths positive leaves 84. The weaker test reaches the same verdict here and would not survive a noisier cube.

A three-dimensional flag rejects instead, per wavelength, non-zero being bad, and is handled by the mask path rather than here.

brainsp.fit_megacube_jax.pop_bin_planes(cfg, age_bins, fit, base, sfr_bins=None, fc_bins=None, bb_bins=None, mass_factor=None)[source]#

Every plane of PoPBins, in order, as (card value, comment, values).

The order is the published one: the featureless continuum first, then the age-binned light fractions, then the age-binned mass fractions, then the fixed tail of scalars ending at SNR. Quantities BRAIN reports and the published megacubes do not are appended after that tail, so a reader that indexes the stack by position rather than by card name still finds everything it knew about where it was.

Age bins may overlap, so totals such as xy_Tot (xyy + xiy) are bins of their own. fc_bins and bb_bins group the featureless components by the power-law exponent or blackbody temperature their names give (ifu_output.featureless_parameter), lower edge exclusive, upper inclusive, as per cent of all the light.

Mstar, Mpcross and the SFR planes are written only when mass_factor is given: 4*pi*d^2/L_sun times the cube’s flux unit, which turns BRAIN’s apparent masses (the observed flux over the library’s flux per unit mass) into solar masses. Without a distance they would carry a unit wrong by that factor, about 3.5 dex for a MaNGA spaxel. The mass fractions, which carry no such factor, are in PoPVecsM and the <pop>_mass planes either way.

The maps follow the definitions of the megacubes of Riffel et al. (2023) exactly, so that the two can be compared map for map:

SFR_<bin> = Mstar * sum(Mini_j %, bin) / 100 / (max - min), in
  Msun/yr: the initial-mass fractions times the present stellar mass;
Mage_L, MZ_L: the stellar sum over the light of EVERY component,
  featureless ones included (Mage_M, MZ_M are unaffected: a
  featureless component has no mass).
brainsp.fit_megacube_jax.fit_cube_hdus(cfg, hdu_list, hdu_flux='FLUX', hdu_ivar='IVAR', hdu_mask='MASK', hdu_flag=None, batch_size=None, progress=None, age_bins=None, flxobs_step=1.0, spaxels=None, stat_type='inv_variance', sfr_bins=None, fc_bins=None, bb_bins=None, galaxy_distance=None, flux_scale=None)[source]#

Fit every selected spaxel of an open cube and return the fit as HDUs.

Separated from run_megacube so that one fit has one implementation whether it is reached from the command line, from the IFU runner with a chain of pre-pass modules in front of it, or from the desktop interface. The arrays, the log grid, the template matrix, the batching and the extensions are all unchanged by the split: run_megacube is now this function plus the file it writes around it.

hdu_flux, hdu_ivar and hdu_mask name the extensions to read, because a pre-pass module renames what it produces – dereddening writes FLUX_DRD, a spectral resampler writes FLUX_BIN – and the fit has to be told which of them it is now looking at. Naming an extension that is not there is an error, not a silent fallback to FLUX, since falling back would fit the cube the user thought they had stopped fitting.

hdu_flag names a per-spaxel selection plane, normally the SN_MASKS_<t> an S/N mask stage wrote.

stat_type says which of the four kinds of uncertainty the statistical extension holds – error, inv_error, variance or inv_variance – and it is converted to the inverse variance the weights are built from on the way in. MaNGA ships an inverse variance and MUSE ships a variance, and a plane read as the wrong one of the two produces weights that are wrong by a factor that varies pixel by pixel and a fit that still looks like a fit.

progress, when given, is called with the number of batches finished and the total. The total is known before the first batch, so this is a real fraction rather than a spinner.

spaxels, when given, is called with the flat spaxel indices a batch has just finished and the spatial shape those indices address, so that an interface can fill the field in as the fit works through it. It is called once with an empty array before the first batch, which is what tells a listener the shape and that nothing is done yet. It is called from the fitting thread and must return immediately; anything it does that takes time is time the fit is not running.

age_bins are the (name, min, max) age bins the PoPBins light and mass maps are summed into, in years, min exclusive and max inclusive. flxobs_step is the step of the linear wavelength grid FLXOBS and FLXSYN are written on, which exists because the analysis tools these files are read with take their wavelength axis from that extension’s CRVAL3 and CD3_3 and have no other route to it.

Returns the products as an HDUList, the cards to add to the primary header, and a summary dictionary. Spaxels that were not fitted, and spaxels whose fit did not converge, are both recorded: STATUS is 0, 1 and 2 for unfitted, converged and not converged, and BADSPXL is 1 for anything that is not a converged fit, so no map plane can be read as a measurement without the reader having been told otherwise.
