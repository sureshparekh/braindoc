brainsp.brain_settings#

BRAIN — reads brain_setup.yaml and turns it into a validated fit configuration.

You do not need to open this file. Edit brain_setup.yaml instead.

python brain_settings.py show the templates available python brain_settings.py –check validate brain_setup.yaml

WHY YAML RATHER THAN PYTHON#

The settings used to be a Python file that BRAIN imported. That works, but it means a stray typo anywhere in it stops the program with a Python traceback instead of a useful message, and a settings file that can execute arbitrary code is a poor thing to email around. This file is parsed, never executed, so the worst a malformed settings file can do is produce a clear error with a line number.

brainsp.brain_settings.AGN_FOLDER = '/home/suresh/PhD/brain_antigravity/brainv2/brainsp/data/libraries/AGN'#

The AGN continuum templates, shared by every stellar library.

An AGN’s featureless continuum has nothing to do with which stellar library describes the host, so it is not a member of any library: include_power_law adds this one set to whichever library is chosen. Seven templates: power laws F_nu ~ nu^-alpha with alpha = 0.5, 1.0, 1.5, 2.0, and Cloudy’s “AGN” incident continuum for big-bump temperatures 1e5, 1.5e5 and 2e5 K. Only their summed light is a measurement: in the optical the three Cloudy continua are power laws of alpha 0.74, 0.64 and 0.59 to within 1.4 per cent, so the split between neighbouring templates is set by noise.

brainsp.brain_settings.load(path='brain_setup.yaml')[source]#

Read the settings file, fill in defaults, reject unknown keys.

A setting that BRAIN used to have and no longer does is answered from RETIRED, with the reason it went, rather than through the unknown-key path. A settings file written for an older BRAIN is a record of a fit somebody ran; the person reading the error is entitled to know what changed underneath them, and ‘did you mean …?’ against the nearest surviving name would be worse than silence. Neither is it ignored: a setting that is parsed and does nothing is the defect this project keeps finding, and the fit it silently changes is one nobody asked for.

brainsp.brain_settings.setting_docs(path=None)[source]#

Each setting’s documentation, read from the documented settings file.

The template’s layout: a setting’s description is the comment block directly above it; a comment block that follows a setting after a blank line continues that setting (notes, examples); a block at the start of a section, before its first setting, introduces the section and is put in front of the first setting’s own text. A comment on the setting’s own line is added at the end. The numbered banner it sits under is its section.

Returns:
dict

{name: {"section": str, "text": str}} for every setting the file documents, in the file’s order.

brainsp.brain_settings.read_catalogue(folder)[source]#

Parse <folder>/CATALOGUE.txt.

Comment lines start with #. Columns:

AGE_YR  Z  FILENAME  SHORT_NAME  MSTARS  KIND

KIND is ‘ssp’ or ‘powerlaw’. It is carried onto every entry, because a component that is not an SSP has no line-spread function of its own and the instrumental-resolution module has to be able to tell it apart from a template that simply forgot to state one.

brainsp.brain_settings.stellar_libraries(root=None)[source]#

The template libraries under root: folders whose catalogue lists at least one stellar population.

A folder with a catalogue is not necessarily a library. AGN/ has one and holds only featureless continua, and offered as a library it fits a spectrum with no stars in it at all.

brainsp.brain_settings.to_config(s, spectrum_file=None)[source]#

Translate validated settings into the object BRAIN runs on.

The two output paths are named here rather than left at the bare file names NewBrainConfig declares. Those names have no folder in them, so a caller that builds a config and fits without overriding them writes its result into whatever directory the process happened to start in, which for anyone running from a checkout is the source tree. Every caller that cared already overrode them; the ones that did not were the ones leaving files in the repository.
