brainsp.optimizer#

NewBrain Optimizer Module — 100% JAX Backend Direct Pixel-Fitting via grid-search initialization + Levenberg-Marquardt.

ALL computation is in JAX — no scipy dependency for the standard mode.

- FFT broadening, dust attenuation, emission lines: JAX matrix ops
- NNLS inner solver: JIT-compiled FISTA
- LM outer optimizer: jax.lax.while_loop + vmap'd numerical Jacobian
- Grid search: jax.vmap across velocity grid

The Jacobian is computed via vmap’d central differences — all 2*n_params perturbations evaluate in a single fused parallel batch.

Supports three photoionization modes:

"spop"     — standard fitting (100% JAX LM)
"nepop"    — nebular continuum from Q(H) subtracted iteratively
"photopop" — self-consistent: predicted H lines replace empirical Gaussians

Bases: object

Direct Pixel-Fitting engine — 100% JAX.

Wraps the nonlinear optimization of kinematic + dust parameters, with internal NNLS solution of linear SSP/gas weights at each step.

All broadening, dust, emission, NNLS, and LM optimization run in JIT-compiled JAX — no scipy dependency (standard mode).

The nonlinear parameter vector is:

[Av, YAV, sigma_star, v0_star, sig_g0, v0_g0, sig_g1, v0_g1, ...]

where g0, g1, … are the kinematic groups.

property inv_sigma#

The per-pixel inverse sigma the fit is weighted by.

Read through a property so that writing to it cannot be separated from invalidating the cached fast_engine constants. Those constants embed the weights, and outlier clipping works by assigning a new array here between two optimize() calls: before this existed the cache key held only the mode and Av_neb, so the second call was handed constants built from the pre-clip weights and every clipped pixel went on being fitted at full weight. The failure was silent – the re-fit ran, converged and returned the same parameters.

A setter is used rather than a hash of the array in the cache key. Hashing costs a pass over the spectrum on every optimize() call, and it still misses an in-place mutation of the array already stored, which is the case that is hardest to see. Invalidating on assignment cannot be bypassed by a caller that does not know the cache exists.

THE GAS DISPERSION LOWER BOUND IS THE USER’S, AND NOTHING RAISES IT

This routine used to raise the lower end of sigma_gas_bounds to the velocity scale, one pixel, behind the user’s back. That existed for one reason: the emission-line profile was a bare Gaussian sampled at pixel centres, which loses flux as soon as the line is narrower than a pixel – 35.7 per cent of it retained at sigma_gas = 10 km/s on a 58.39 km/s grid – so a narrow line was silently deleted rather than fitted. The profile is now integrated over the pixel in the Fourier domain and is exact at every width including exactly zero, so the reason is gone and the floor is only harm: the pixel-integrated line is broader at a given sigma_gas than the centre-sampled one was, and with the floor in place both kinematic groups of the reference spectrum sat on it, unable to reach the narrower dispersion that fits better. A parameter pinned at a bound is not a measurement, and a bound nobody asked for makes every sigma_gas the code reported a statement about the grid rather than about the gas.

What is left is the bound the user sets, gas_dispersion_range, whose shipped lower end is 1.0 km/s. That is below the thermal width of every ion in the line catalogue at T_e = 10^4 K – 9.1 km/s for hydrogen, 1.2 km/s for iron, sqrt(k T_e / A m_u) – so no fit that reaches it is measuring a line width. It is positive rather than zero because the profile depends on sigma only through sigma^2, so the gradient vanishes at zero and a fit that arrives there has nowhere to go; and because a printed 0.00 km/s invites being read as a dispersion of zero, which Westfall et al. 2019 Section 7.6.3 is explicit that a sub-instrumental width is not. A bound of this size (velscale/100 would be 0.58 km/s on this grid) is the usual defensive choice; 1.0 km/s is of that order and, unlike a fraction of the velocity scale, is a number the user can read in their settings file and change.

The megacube path builds its bounds straight from sigma_gas_bounds and never had the floor, so the two paths now search the same box.
