brainsp.brain_ifu#

BRAIN — the IFU runner.

python -m brainsp.brain_ifu run  my_pipeline.json
python -m brainsp.brain_ifu check my_pipeline.json
python -m brainsp.brain_ifu defaults > my_pipeline.json

A pipeline is an ordered chain of pre-pass modules followed by the fit, run over a list of targets. Each target is opened once, every stage appends the HDUs it produced to that open list, and the list that accumulates is the megacube, in the format of the MaNGA megacubes of Riffel et al. (2023, MNRAS 524, 5640), so a megacube BRAIN writes opens in tooling written for those.

Targets run one after another rather than in parallel. A single cube’s batch already saturates the machine through XLA’s own thread pool, so a second cube alongside it contends for the same cores and doubles peak memory for no throughput.

The chaining of extension names between stages lives here rather than in the desktop interface, so the command line gets it too: a resampler run on the flux and on the inverse variance produces FLUX_RSP and IVAR_RSP, dereddening produces FLUX_DRD, and the fit is handed whatever the last stage called its output. Getting one of those names wrong by hand fails late, inside the fit.

brainsp.brain_ifu.age_bin_errors(rows)[source]#

What is wrong with a set of age bins, before a cube is opened.

Bins may overlap: a total such as xy_Tot (all of xyy and xiy) is a bin of its own, and each bin is its own map, so nothing is counted twice within a map (the bins’ maps are not meant to be added). Bins may also leave gaps – the published sets do – and the fit reports how much light falls into no bin.

class brainsp.brain_ifu.BrainFit(**kwargs)[source]#

Bases: IFUModule

The batched fit, as a stage of the chain. Writes the fit extensions.

Every physics setting comes from the settings file named in settings, exactly as for a single spectrum: the template library, the fitting range, the extinction law, the nebular mode, the solver and the bounds all have one place they are declared. What belongs here is only what is about the cube – which extension holds the flux, which the uncertainty and of which kind, which plane selects the spaxels to fit, and how large a batch to compile for.

Three keys override the settings file per target, because they are the three that legitimately differ between cubes in one run: redshift sets cube_redshift, mask file sets mask, and wavelength scale sets wavelength_scale. Left at None, the settings file’s own values stand.

wavelength scale is here rather than in the settings file’s exclusive keeping for the same reason redshift is: it is a fact about the instrument that produced this cube, not about the physics being fitted, and a run that sweeps cubes from two surveys has two answers to it. It takes ‘air’ or ‘vacuum’ and nothing else; the validator refuses every other spelling by name, so the control that sets it emits the exact token rather than anything it has had to case-fold.

There is no timeout: a vmapped batch has a fixed iteration count and cannot hang on one spaxel.

brainsp.brain_ifu.build_module_chain(cfg)[source]#

The enabled stages, in order, with the extension names already threaded.

Returned as (class name, configuration) pairs rather than as constructed objects so that the same function serves the live runner and the script exporter, and the exported script therefore cannot describe a pipeline different from the one the runner would have executed.

The threading is the part that is easy to get wrong by hand. A resampler or a degrader runs twice, once on the flux and once on the statistical plane with the data type set so the two combine correctly, and each pass renames its output; dereddening always writes the fixed name FLUX_DRD; the S/N mask writes SN_MASKS_<threshold>, which the fit then consumes as its selection plane. Each stage is handed the name the stage before it produced.

A stage that changes the shape of the cube drops the data-quality mask rather than carrying one that no longer lines up with the data: a flag is not an additive quantity, so there is no honest way to block-sum it or to interpolate it onto a new wavelength grid.

Every per-target override key the enabled stages of this chain declare.

Which keys those are depends on which stages are switched on, so the set is derived from the chain rather than listed somewhere: an interface offering a column the chain has no reader for is offering a column that does nothing.

brainsp.brain_ifu.override_column_errors(cfg)[source]#

Refuse a per-target column no stage in the chain would read.

A module ignores a key it never declared, which is what lets one row carry columns for several stages – and is also how a column named ‘reddening’ instead of ‘ebv’ runs a whole campaign at the wrong extinction without a word. The keys are known before the run, so the mismatch is caught here instead of being discovered in the output.

brainsp.brain_ifu.sn_method_problem(cfg)[source]#

Why the S/N method cannot read the uncertainty the cube has, or None.

The S/N stage is handed the uncertainty extension under the name its method reads (ivar, var, error), whatever that extension holds. An ivar formula given a 1-sigma error computes mean(flux * sqrt(error)), which for a JWST cube in erg/s/cm^2/A is of order 1e-28: every spaxel falls below every threshold and the fit is handed nothing.

brainsp.brain_ifu.missing_extensions(cfg, path)[source]#

The extensions the run reads that the cube at path does not have.

Checked before anything runs: a name the file lacks used to surface as a KeyError from inside whichever stage first needed it, after the run had started, with nothing pointing at the field that named it.

brainsp.brain_ifu.validate_detailed(cfg, check_paths=True)[source]#

Everything that can be refused before a single spaxel is read, each message paired with the section of the pipeline it is about.

The pairing is what lets an interface put a message next to the control that is wrong instead of only in a dialog, and it belongs here rather than in the interface because the code that decides a setting is wrong is the only code that knows which setting it was.

check_paths=False skips the existence tests, so a pipeline can be configured against a directory that only exists on the machine it will eventually run on. Everything else is checked either way, because a threshold that does not match, or a stage chain that produces nothing, is wrong on every machine.

class brainsp.brain_ifu.BrainIFU(progress=None, log=None, spaxels=None)[source]#

Bases: object

A chain of stages run over a list of targets.

add_module, add_target and execute. Targets run sequentially, the progress callback reports real fractions of the work done, and every stage is constructed once per target so a per-target override reaches it.

spaxels is the finer of the two progress callbacks: the fit reports the spaxels each batch finished as it finishes them, so an interface can show the field filling in. It runs on the fitting thread, so a listener that does real work in it slows the fit down.
