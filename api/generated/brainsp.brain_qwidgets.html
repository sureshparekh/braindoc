brainsp.brain_qwidgets#

BRAIN GUI — custom Qt widgets.

Qt has no dual-handle range slider and no segmented control, so both are drawn here. Everything takes its colours from the active palette, so the light/dark switch reaches every pixel.

paintEvent(_)[source]#

A track, the span between the handles, and two handles.

The accent used to paint the whole track, both handles and every tick, which is most of a panel’s width given to the one colour that is supposed to mean something. It now marks the span that is selected and the handle being touched, and the rest of the control is drawn in the neutral ramp.

The values sit under their own handle rather than pinned to the ends of the widget, so reading one does not mean working out which end it belongs to, and they are clamped so neither runs off an edge.

Catalogue ticks are drawn above the track rather than below it. Below, they are the lowest thing the control paints and they collided with the label of whatever the layout put next; above, they sit between the numbers and the track they belong to and nothing can reach them.

class brainsp.brain_qwidgets.Segmented(options, init=0, parent=None)[source]#

Bases: QWidget

One row of mutually exclusive buttons.

An option can be marked unavailable, which disables its button, strikes its label through and puts the reason on it as a tooltip. A choice the run would silently ignore is worse than no choice at all: the fit finishes, the numbers look ordinary, and nothing says the setting did not apply. The strikethrough carries the same message as the greying, so the state does not depend on seeing colour.

setProperty(name, value)[source]#

Carry error down to the buttons that are actually painted.

A Segmented is a layout holding push buttons and paints nothing itself, so a stylesheet rule keyed on a property of the container reaches no pixels. An unanswered control that has been told it is in error and shows nothing is worse than one that was never asked: the caller believes the user has been warned. The flag is pushed onto the children, which are the things with a border.

Put the control back to unanswered, the state init=None also means.

setValue cannot express it: a name that is not an option is ignored, so handing it None leaves whatever was chosen before still chosen. That matters when a saved configuration is loaded over a page a user has already touched – without this, a file that declares no answer inherits the last one and the page shows a setting the file does not contain. class brainsp.brain_qwidgets.Disclosure(title, count=None, parent=None)[source]#

Bases: QWidget

A heading that folds a group of controls away, shut by default.

Every setting BRAIN accepts has to be reachable, but a panel that shows all of them at once is a wall of spin boxes in which the handful that change a result are no easier to find than the solver tolerances. The ones that decide the physics stay in the open; the rest live behind one of these, which states how many settings it holds so their existence is visible even when their controls are not.

class brainsp.brain_qwidgets.Plate(title, checkable=False, parent=None)[source]#

Bases: QWidget

A panel with a heading, and no bevel anywhere on it.

A QGroupBox draws a sunken frame with its title notched into the top edge. That frame is the most recognisable mark of an interface nobody has looked at, and the title inside it repeats a heading the sidebar has already said, so the same four words arrived three times on one screen. What is left here is a surface one value above the page, a heading in the interface grotesque, and the form beneath it. Depth comes from value, as it does everywhere else in this application.

An optional stage carries a checkbox in place of its heading rather than beside it, because the heading IS the thing being switched on, and the body is disabled rather than hidden when it is off: a stage that disappears when it is not running cannot be read to find out what it would have done.

brainsp.brain_qwidgets.label(text, kind='FieldLabel')[source]#

A label, wrapping only where wrapping is what it is for.

Every label used to word-wrap. A word-wrapped QLabel reports its height as a function of its width, and a QScrollArea that is resizable asks its content for a height before the content knows how wide it will be. The answer comes back short, the layout takes the difference out of whichever items can give it, and a one word field label is squeezed to no height at all and paints on top of the control above it. The prose labels still wrap, because a paragraph has to; Age and Metallicity never did.

brainsp.brain_qwidgets.LABEL_COL = 136#

The width of every panel’s label column, in pixels.

A QFormLayout sizes its label column to its own longest label, so each panel found a different one and the fields started at a different x in every panel down the page. Fixing the column makes one vertical edge that every control on the page is aligned to, which is the thing a column of settings is read down.

class brainsp.brain_qwidgets.FieldForm[source]#

Bases: QFormLayout

A form whose field column starts in the same place in every panel, and whose prose starts there too.

Two alignment faults came from the plain QFormLayout. The field column moved from panel to panel, because each form measured only its own labels. And a caption added as a single widget spanned both columns, so the paragraph explaining a control began at the panel’s left edge while the control it explains began a hundred-odd pixels to the right, with the text running the full width of the plate and touching both edges.

Here a label is given the fixed column, and a wrapping caption is indented to where the fields begin. Labels sit to the left of that edge; everything else – field, button, table, paragraph – begins on it.

brainsp.brain_qwidgets.row(*widgets, stretch=None)[source]#

Widgets side by side, with None standing for a spring.

A horizontal layout gives space it has no instruction for to whichever children will take it, and a QLabel will. Two call sites asked for a trailing spring by naming a stretch index one past the last widget, which matches nothing, so the slack went to the labels instead and opened arbitrary gaps in the middle of a row of steppers. Passing None puts the spring where it is meant to go and is visible in the call.

class brainsp.brain_qwidgets.Strip(parent=None)[source]#

Bases: QWidget

A row that drops its least important parts before anything overlaps.

Qt will happily let two labels in one layout paint over each other rather than admit the row does not fit, which is how a strip that reads cleanly at 1500 pixels turns into overlapping text at 1000. Each optional child is registered with the width below which it goes, widest-first, and the row hides them in that order on every resize.
