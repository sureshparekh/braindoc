brainsp.emission_lines#

Tied doublets, kinematic groups, and the Gaussian design matrix, with per-group velocity and dispersion for the joint fit.

The wavelengths, the species table and the default kinematic groups are NOT here. They live in line_catalogue, which imports numpy and nothing else, so the settings validator and the desktop interface can ask what lines exist without starting a JAX backend in the process that draws the menus. This module imports JAX and is therefore the wrong place for pure data.

The names imported at the top are re-exported rather than redefined, so from emission_lines import LINE_SPECIES keeps meaning exactly what it meant. They are one table with two import paths, not two tables. New code should read them from line_catalogue, which costs no JAX backend.

Nothing here derives meaning from the shape of a catalogue name. Every entry’s species is declared in LINE_SPECIES, every doublet names its components rather than repeating their wavelengths, and group membership is looked up by species rather than matched as a string prefix. That is not tidiness. Each of the three couplings this replaces failed silently:

- Kinematic groups were assigned by name.startswith(prefix), and "He I" is
  a prefix of "He II", so He II_4686 -- a high-ionisation line -- was
  placed in the low-ionisation group. Measured, not hypothetical.
- Free lines were removed from the catalogue when a tied doublet already
  covered them by testing the wavelength for membership of a set of
  floats. Exact float equality held only while both numbers were
  whole-Angstrom literals written twice. Store the doublet's wavelength to
  more decimals than the line's and the deduplication stops working, the
  same wavelength gets two columns, the gas block goes rank-deficient, and
  a non-negative solver splits the flux between them at an arbitrary
  vertex without complaining.
- Line fluxes were extracted by substring, returning the first name that
  contained the key. "[S II]" returns 6716 and silently discards 6731,
  which is half the density diagnostic; "[O III]" returns the 4363
  auroral line rather than the doublet; "He I" returns He II. It happens
  not to misfire today only because the two keys in use, Halpha and
  Hbeta, are unambiguous in the shipped catalogue.

Every entry point that produces wavelengths takes the observed spectrum’s wavelength scale as a required argument. There is no default, because a default is a guess: a wrong guess moves every line by about 83 km/s, which the fitted gas velocity absorbs almost entirely, so the fit converges and nothing in the output looks wrong. See line_catalogue for the conversion and brain_settings for the refusal.

brainsp.emission_lines.TIED_DOUBLETS = {'[N II]_Doublet': [('[N II]_6548', 0.32739), ('[N II]_6583', 1.0)], '[O III]_Doublet': [('[O III]_4959', 0.3351), ('[O III]_5007', 1.0)], '[S III]_Doublet': [('[S III]_9069', 0.40506), ('[S III]_9531', 1.0)]}#

Pairs whose relative flux is fixed by atomic physics rather than by the fit.

Every pair here is the 1D2 - 3P1 and 1D2 - 3P2 transition out of ONE upper level, so the intensity ratio is A(1D2-3P1) E(1D2-3P1) divided by A(1D2-3P2) E(1D2-3P2) and nothing else. It is EXACTLY independent of electron temperature, electron density, ionisation parameter and abundance: both photons leave the same level, so whatever sets how often that level is populated cancels identically. There is no modelling choice to make and no ratio to fit, only the right number, and a number rounded to two figures is simply a wrong one.

The weak component’s ratio is quoted relative to the strong component, which carries 1.0, because a doublet column is the ratio-weighted sum of area-normalised profiles: the fitted weight is then the flux of the ratio-1.0 line, which is the quantity the BPT calibrations and the line table report. doublet_nebular_sum_factor is the one conversion to the sum over both components, for the one diagnostic that wants a sum.

[O III] 4959/5007 and [N II] 6548/6583 are the relativistically corrected values of Storey & Zeippen (2000), MNRAS 312, 813, Tables 3 and 4, whose A-value ratios become 0.33510 and 0.32739 once scaled by the ratio of transition energies. THE CITATION IS EXPLICIT BECAUSE OLDER ATOMIC DATA DIFFER: the Froese Fischer et al. (2004) data for N II give 0.3399, 3.8 per cent away from the value here, and a comparison against results built on them will show that difference in [N II]; it is not a BRAIN defect.

[S III] 9069/9531 is NOT from Storey & Zeippen, whose calculation covers the carbon and oxygen sequences to Z = 12 only; S III is the 3p2 analogue and is outside it. 0.40506 is Froese Fischer, Tachiev & Irimia (2006), ADNDT 92, 607, as compiled by Podobedova, Kelleher & Wiese (2009). The 0.41 it replaces corresponds to no published calculation: the same data sets give 0.40322 (Mendoza & Zeippen 1982) and 0.39435 (Tayal, Zatsarinny & Sossah 2019), so 0.41 was not a different choice of source either.

Three further homologous pairs appear in the same tables and are deliberately NOT tied. [O I] 6363/6300 = 0.33034 and [Ne III] 3968/3869 = 0.30868 have only their strong component in the catalogue, so there is no pair to tie. [C I] 9824/9850 = 0.32024 has both components, carried as two independent lines; tying them would change what the NIR fit is free to do, which is a separate decision from correcting a ratio already in use.

brainsp.emission_lines.doublet_nebular_sum_factor(name)[source]#

The factor taking a fitted doublet weight to the sum over its components.

A doublet column is built with its components’ ratios relative to the strong one, and each component profile is area-normalised, so the fitted weight is the flux of the ratio-1.0 component alone. Most consumers want exactly that – the BPT diagram is calibrated on [O III] 5007 and [N II] 6583, not on doublet sums – but the [O III] temperature diagnostic wants the nebular sum F(4959) + F(5007), and multiplying by this factor is what supplies it.

Derived from the catalogue entry rather than written out again at the point of use, because the factor IS one plus the branching ratio. A second copy of that number is a second thing to keep in step with the design matrix, and the whole point of a branching ratio fixed by atomic physics is that there is one of it.

Dividing by the largest ratio rather than assuming it is 1.0 keeps the factor right for a doublet whose ratios were written on some other scale.

brainsp.emission_lines.drop_masked_lines(lines, doublets, wavelength, weight, sigma_kms)[source]#

Leave out the lines whose centres the mask (or a gap in the data) covers.

A line is dropped when fewer than half of the pixels within its rest wavelength +- 2 sigma (at sigma_kms, and never less than two pixels either side) carry weight. Its amplitude is then set by a wing or by nothing, and the fit returns an arbitrary flux: a masked H-alpha came back at 35 times its true value, and an [N II] 6583 with only its red wing outside a mask at 77 times. A few bad pixels on a line do not drop it; a masked window or a gap in the spectrum over its core does. A doublet loses only the members that are covered; one survivor is fitted alone, at ratio 1, under its own name, as for a doublet that loses a member to the edge of the grid.

Parameters:

{name: rest_wavelength}.

The fitting grid.

Per-pixel weight on that grid; zero where nothing is fitted.

Generate emission line template matrix with per-kinematic-group parameters.

The profiles come from _build_emission_jit, one kinematic slot per column, rather than from a Gaussian written out again here. There used to be a second implementation in this function, and a second implementation of a line profile is a second thing to keep in step: the compiled path had already lost the 8-sigma truncation this one applied, so the two paths differed in the far wings before the pixel integration went in and would have differed in the core after it.

brainsp.emission_lines.group_positions(line_groups)[source]#

The position each kinematic group label occupies in the parameter vector.

A group label is whatever the user wrote in line_groups: any hashable, in any order, with any gaps. The fitted parameter vector, in contrast, is a flat sequence, and both the scalar optimizer and the cube path lay the per-group sigma and v0 out by walking sorted(set(line_groups.values())) and appending two slots per group. So the label is a name and the position is an index, and the two coincide only for labels that happen to be 0, 1, 2, … in order.

DEFAULT_GROUP_SPECIES uses 0 and 1, so they did coincide, and precompile_line_table shipped the raw label where an index was needed. A settings file saying line_groups: {1: […], 2: […]} then made label 2 index a length-2 array; an out-of-bounds gather in JAX is clamped rather than raised, so every line in group 2 silently took group 1’s dispersion and velocity and the fit ran to completion.

Defined here, once, so that the table and the parameter vector are derived from the same expression rather than from two that agree by inspection.

brainsp.emission_lines.reachable_window(rest_wavelength, v0_gas_bounds, sigma_gas_max)[source]#

The span of observed wavelength a rest wavelength can be moved to.

A line is shifted by the fitted gas velocity and spread by the fitted gas dispersion, and the fit may choose either anywhere inside its bounds. So the widest reach is the bluest allowed velocity minus a few dispersions, to the reddest allowed velocity plus a few. Three dispersions is the same reach brainv1 uses when it restores masked pixels around a line, and at three sigma a Gaussian still carries 1.1 per cent of its peak, which is a contribution a fit can act on.

Returns (lowest, highest) in Angstrom.

brainsp.emission_lines.precompile_line_table(wavelength, lines, doublets, line_groups, v0_gas_bounds, sigma_gas_max)[source]#

Pre-compute a fixed-shape emission line table for JIT-compatible use.

Packs single lines (1 component) and doublets (2+ components) into padded JAX arrays so _build_emission_jit can run without Python control flow.

Parameters:
wavelength1D array

Wavelength grid.

linesdict

{name: rest_wavelength} single lines.

doubletsdict

{name: [(component_name, wl, ratio), …]} tied doublets.

line_groupsdict

{name: group_label} kinematic group assignments.

v0_gas_bounds(float, float)

The gas velocities in km/s the fit is allowed to try.

sigma_gas_maxfloat

The largest gas dispersion in km/s the fit is allowed to try.

Returns:
tabledict

A dictionary with these keys:

'names'           : list of str (Python, not traced)
'rest_wavelengths': (n_lines, max_comp) JAX array, 0-padded
'ratios'          : (n_lines, max_comp) JAX array, 0-padded
'n_components'    : (n_lines,) int array
'group_indices'   : (n_lines,) int array, POSITIONS into the fitted
                    per-group sigma and v0 arrays, not labels
'group_labels'    : list (Python, the labels themselves, for output
                    bookkeeping)
The two group entries are deliberately different quantities and
deliberately differently named. ‘group_indices’ is what the compiled
kernel gathers with, and it must be a position; ‘group_labels’ is what
the user called the group, and it is what a summary should print. See
group_positions for the failure that followed from conflating them.
A line whose name is absent from line_groups raises. It used to default
to group 0, which is a guess: the caller that built lines and doublets
and the caller that built line_groups had gone out of step, and putting
the orphan in whichever group happens to sort first hides that.
WHICH LINES ARE ON THE GRID
get_line_catalog selects candidates with a fixed 500 A margin, which is
about coverage and knows nothing about the fit. A candidate that cannot
reach the grid at any velocity and dispersion inside the bounds used to
be kept anyway, and it entered the design matrix as a column of exactly
zero: the non-negative solve went rank-deficient, the weight came back
0, and the summary reported the line as a non-detection. It was never
fitted. Saying nothing about a line that was not measured, in the same
table as lines that were, is the failure this whole module exists to
stop, so such a line is dropped from the table and named in the log.
The bounds are arguments rather than a margin invented here, because
the reach that matters is the one the fit is actually permitted, and
only the caller knows it. See reachable_window.
PARTIAL DOUBLETS
A tied doublet with one component on the grid and one off is kept, as
the surviving component alone: its ratio is renormalised to 1.0 and the
entry takes that component’s own catalogue name. The alternative –
keeping the doublet’s name and the survivor’s branching ratio – puts a
column holding one line under a name that every consumer reads as the
sum of two, so the fitted flux of “[O III]_Doublet” would silently be
0.33 of one line rather than 1.33 of both. Renaming makes the entry say
what it is, and gas_diagnostics already resolves a doublet request to
the components of that species when the doublet name is absent.
