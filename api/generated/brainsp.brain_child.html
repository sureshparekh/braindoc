brainsp.brain_child#

BRAIN, one fit, in a process of its own.

JAX fixes its backend the first time it is used in a process and keeps it for the life of that process. A desktop interface has already used JAX by the time anybody presses Fit, so a device selector that writes JAX_PLATFORMS into the running interpreter selects nothing. The only place the variable is still read is before Python starts, which means the fit has to run somewhere Python has not started yet: here.

The interface launches this module with python -u brain_child.py job.json and an environment that already names the platform. The job file carries the whole configuration, so nothing is inherited except the environment, and nothing is pickled, so there is no fork and no threaded-JAX deadlock to inherit either.

Everything travelling back to the interface goes out on standard output as one JSON object per line. Anything the fit prints is turned into a log message rather than written straight out, so the stream stays parseable however talkative the fit becomes. Standard error is left alone: the parent reads it separately and keeps the tail of it to explain a process that dies without saying why.

The backend actually in use is compared with the one that was asked for before any fitting starts, and a mismatch ends the run. A device selector that accepts a request it cannot honour is worse than one that refuses, because the result looks the same either way.

brainsp.brain_child.set_platform(device)[source]#

Name the platform JAX is to use, before anything imports JAX.

The parent already put this in the environment, which is the copy that matters; repeating it here makes the module runnable on its own and makes the mapping visible in one place. “gpu” is not a platform name JAX 0.10 accepts: it expands to cuda and rocm, and an interpreter without rocm refuses the whole list. The platform is cuda and the backend it reports is gpu, which is why the two tables below are not the same table.

brainsp.brain_child.confirm_backend(device, channel)[source]#

Refuse to fit on a device other than the one that was asked for.

Reading the backend is what initialises it, so a request for a device this machine does not have raises here rather than quietly falling back. The comparison after it catches the rest: anything that leaves JAX on a different platform than the environment named ends the run through the failure channel instead of producing a fit whose provenance is wrong.

brainsp.brain_child.config_from_dict(values)[source]#

A NewBrainConfig rebuilt from the JSON the interface wrote.

JSON has one sequence type, so every bound arrives as a list where the fit expects a tuple. Each field whose declared default is a tuple is put back into one and nothing else is touched, which round-trips the reference configuration field for field.

brainsp.brain_child.run_spectrum(job, channel)[source]#

One spectrum, fitted, with the interface’s two caches honoured here.

The order is the order the caching layer requires: the kernel cache is turned on before anything touches a device, the backend is confirmed next, and the template loader is replaced only after that, so a run that is about to be refused for the wrong device never reads a template.

brainsp.brain_child.run_spectra(job, channel)[source]#

A table of spectra, fitted one after another in this one process.

The point of fitting them here rather than one process each: JAX compiles the fit once, for the first spectrum, and every later spectrum on the same wavelength grid reuses that compiled code; the templates are read once and kept. Each spectrum is reported as it finishes, and one that fails is reported and skipped, so the rest of the table still runs.

brainsp.brain_child.run_cube(job, channel)[source]#

One campaign of datacubes, with its progress reported as it happens.

The spaxel callback runs on the fitting thread, so it does the least it can: one line on the channel and back. An empty index list is the fit saying how large the field is before it starts.
