brainsp.fit_datacube#

Parallel Datacube Fitter for NewBrain Fits an entire MEGACUBE or FITS datacube in parallel.

The templates and the log-lambda grid are built once and shared by every spaxel, so the line-spread-function correction is applied once, to that one matrix, before the pool is launched. It is not a per-spaxel cost. The mask the decision is taken over is the union of the pixels the fitted spaxels will use; cube_fitted_pixels says why.

Each spaxel’s own dispersion is then reported twice: sigma_star as the kernel applied it to the library, and sigma_star_corrected with the remaining difference in line-spread functions taken out of it in quadrature. When ‘instrumental_resolution’ is not set the corrected value is None rather than a copy of the observed one, so nothing downstream can mistake an observed dispersion for an intrinsic one.

brainsp.fit_datacube.spaxel_pool(num_threads)[source]#

A pool of threads, not of processes.

multiprocessing.Pool forks, and JAX is already multithreaded by the time the fork happens, so the child inherits locks held by threads that do not exist in it. The pool then deadlocks with no error and no traceback: this module used to hang indefinitely on four spaxels, with Python’s own “os.fork() was called” warning as the only sign that anything was wrong.

Threads have no such problem and lose nothing here, because the work is inside compiled XLA kernels, which release the interpreter lock for their whole duration.

brainsp.fit_datacube.bases_info_for(cfg)[source]#

The template list, chosen the way brainv1 chooses it.

A configuration built by brain_settings.to_config carries bases_entries, the (age, Z) selection read from the library’s CATALOGUE.txt. The cube fitters used to skip that and fall through to a filename scan for ‘_baseFe’, which matches nothing in the shipped library, so driving them from brain_setup.yaml produced zero templates and an IndexError on an empty matrix.

brainsp.fit_datacube.cube_fitted_pixels(flux_cube, ivar_cube, wl_lin, lam_grid)[source]#

The pixels the line-spread-function decision is taken over, for a cube.

One template matrix is shared by every spaxel, so the decision to convolve a group of templates or to leave it at its native resolution is taken once and then binds all of them. A single spaxel’s good-pixel mask is therefore the wrong unit: a convolution justified on one spaxel’s window would be pushed onto spaxels that fit pixels where it is not justified.

The union of the good pixels over the spaxels that will actually be fitted is used instead, intersected with the template coverage by the caller. Of the three masks on offer it is the conservative one: prepare_templates refuses a group of templates when the data is narrower than the library anywhere in the mask, so widening the mask can only turn a convolution into a refusal, never a refusal into a convolution, and a refusal leaves the templates untouched and says so in the log. The intersection would let a group be convolved on the strength of a window narrower than any spaxel really fits; the coverage mask on its own would carry pixels that every spaxel has already thrown away.

The union is exact, not an approximation. A spaxel fits the pixels where the interpolation of its error array onto the log grid comes out positive, and that interpolation is a convex combination of the two bracketing samples, so interpolating the per-wavelength indicator “some fitted spaxel has a usable inverse variance here” is positive on exactly the union.

brainsp.fit_datacube.to_rest_frame(wl, cfg, logger)[source]#

Put an observed-frame cube onto rest wavelengths.

The two entry points take different frames, and that asymmetry is the kind of thing this code fails silently on, so it is stated here and in brain_setup.yaml rather than left implicit. The scalar path expects a spectrum you de-redshifted yourself; a datacube arrives straight from the telescope in the observed frame, so the cube paths do it before any spaxel is fitted.

Applied to the wavelength axis rather than to the flux, and before the log grid is built, so every template, mask and line window downstream is in one frame. Nothing is interpolated and no flux is touched.

cube_redshift and spectrum_redshift do opposite jobs and setting both is refused in brain_settings.validate, so reaching here with a non-zero value means exactly one correction is wanted.

brainsp.fit_datacube.spaxel_inputs(flux_lin, ivar_lin, mask_lin, wl_lin, lam_grid, file_weight_lin, norm_wavelength)[source]#

One spaxel’s flux and inverse sigma on the log grid.

Named and separate so that there is exactly one definition of what a spaxel looks like by the time it reaches the fitter, and so that it can be compared against the scalar path without running a fit. It follows brainv1 step for step, because any step where it does not is a place the same spectrum gets two different answers depending on which entry point was used.

The error array keeps its values at rejected pixels rather than being zeroed there, because the rejection is carried by the weight and by the clean fraction, not by the error. Zeroing it instead would interpolate a real error against a zero at every pixel next to a rejected one, which changes the weight of pixels that were never in question. Where the inverse variance carries no information at all the error is filled the way load_spectrum fills it, ten times the median, so that the two entry points agree pixel for pixel.

The two mask carriers are both needed and do different jobs. The nearest-neighbour weight says which input pixel an output pixel sits on top of. The clean fraction says how much of the output pixel’s value came from input that was worth keeping, which is the question nearest-neighbour cannot answer: log-rebinning is a flux-conserving redistribution, so where the output bin is wider than the input bin it blends neighbours, and a pixel whose nearest input was good can still hold flux from a rejected one next door.
