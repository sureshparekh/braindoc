brainsp.brain_subprocess#

BRAIN, the interface’s end of a fit that runs somewhere else.

One class, ChildRun, which is a QThread whose entire job is to own a child process, hand it a configuration and turn the lines it sends back into Qt signals. The pages that use it subclass it, declare the signals they already declared, and say what each kind of message means to them, so the rest of the interface sees exactly the API it saw when the fit ran in a thread.

The reason for the process rather than the thread is JAX. It fixes its backend the first time it is used and never changes it, so the device selector can only be honoured by an interpreter that has not started yet. Starting one is also what makes a Stop button able to stop anything and what keeps a crash inside the fit from taking the interface with it.

The child is started with subprocess.Popen, not with a fork of this process: BRAIN has a history of forking an interpreter that already held threaded JAX state and deadlocking, and a fresh interpreter cannot inherit a trap it never had.

Bases: QThread

One child process, owned for as long as it runs.

job is whatever the child needs and nothing else; it is written to a temporary file outside the project and deleted afterwards, because a configuration is far larger than a command line should carry and because passing it as a file means the child reads it with json and not with an argument parser.

Subclasses implement handle, which receives one decoded message at a time on this thread, and report_failure, which is called for the failures the child could not report itself: a process that died without a word, and a run that was stopped.

environment()[source]#

This process’s environment with the platform named in it.

Named before the child starts, which is the only moment JAX reads it. “gpu” is not a value JAX accepts; the platform is cuda. “auto” removes the variable rather than setting it to something, so a selector left alone behaves as an interpreter with no JAX_PLATFORMS at all.

cancel()[source]#

Stop the run by ending the process doing it.

SIGTERM first, because a Python process ends cleanly on it and leaves no half-written output; SIGKILL five seconds later from a watcher, so a child stuck inside a compiled kernel that never returns to the interpreter still goes away. The watcher is a plain thread because it does nothing but wait.
