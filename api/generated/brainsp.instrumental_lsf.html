brainsp.instrumental_lsf#

BRAIN — instrumental resolution and the line-spread function.

The data and the template library almost never share a line-spread function, and the difference between them lands directly on the fitted stellar velocity dispersion. This module measures that difference, brings the library up to the data’s line-spread function once at load time, and refuses when the library is the broader of the two.

Observed frame against rest frame. The templates live at rest wavelengths, and so does a spectrum that was de-redshifted before BRAIN saw it, but the spectrograph smeared the light at the wavelength it was recorded at. So sigma_inst is looked up at lambda_rest * (1 + z) while sigma_lib is looked up at lambda_rest, and the two are compared in km/s, a currency in which the (1 + z) factor cancels. spectrum_redshift is the redshift that was removed from the spectrum before BRAIN saw it.

The data is never smoothed. The other way to match two line-spread functions is to degrade the better one, which when the library is broader means convolving the spectrum. Every chi2 in this code is formed with a diagonal inverse variance; smoothing correlates neighbouring noise samples, so chi2 drops for a reason that is not a better fit. When the library is broader BRAIN fits at the library’s native resolution and says in the summary what that costs.

brainsp.instrumental_lsf.removed_redshift(cfg)[source]#

The redshift taken out of the data before the fit, whoever took it out.

A spectrum’s is spectrum_redshift, whether you removed it before handing the spectrum over or BRAIN removed it (spectrum_in_rest_frame: false). A cube’s is cube_redshift, which BRAIN always removes itself. brain_settings refuses both at once, so at most one is non-zero.

Only spectrum_redshift used to be read here. A cube fitted at z > 0 has spectrum_redshift = 0, so the instrument’s resolution was looked up at the rest wavelength instead of the observed one: harmless for a constant R, wrong by a factor (1 + z) for a resolution given in Angstrom, and at the wrong place on a resolution curve.

brainsp.instrumental_lsf.parse_resolution(value, setting_name)[source]#

Turn one setting into a resolution descriptor.

Returns:
dict or None

Descriptor with a ‘kind’ of ‘angstrom’, ‘kms’ or ‘table’, plus a ‘text’ field naming it for the log and the summary.

Notes

Accepted forms:

None

No information. Returns None.

a number

Full width at half maximum in Angstrom, constant with wavelength.

“2.51 A” / “2.51 A FWHM”

The same thing written out.

“2.51 A sigma”

A dispersion in Angstrom rather than a full width.

“45 km/s”

Constant in velocity. Read as a dispersion, because that is the convention every library that quotes one uses: template headers say vd (km/s), and vd is a sigma. Write “45 km/s FWHM” if you mean a full width.

a path to a file

Two columns, wavelength in Angstrom and full width at half maximum in Angstrom, interpolated onto the fitted grid.

The frame the tabulated wavelengths are read in is decided by the setting, not by this parser, which serves both. instrumental_resolution is evaluated at observed-frame wavelengths, lambda_rest * (1 + z), because a line-spread function is a property of the spectrograph and the spectrograph saw the light there. library_resolution is evaluated at rest wavelengths, because that is where the library lives.

A unit is required on any string form. “2.51” and “2.51 FWHM” are refused rather than assumed to be Angstrom, because the same two characters of ambiguity between Angstrom and km/s is a factor of twenty on the answer.

brainsp.instrumental_lsf.sigma_angstrom(descriptor, lam, lookup_lam=None)[source]#

Evaluate a resolution descriptor as a dispersion in Angstrom.

Parameters:
descriptordict

From parse_resolution or read_library_headers.

lam1D array

The wavelengths the returned widths belong to. Widths come back in the units of this axis.

lookup_lam1D array or None

The wavelengths at which the descriptor is evaluated, when that differs from lam. This is how a line-spread function tabulated in the observed frame is used on a rest-frame grid: look up at lambda_rest * (1 + z), and the width returned is then rescaled by lam / lookup_lam to land back on the rest-frame axis.

brainsp.instrumental_lsf.sigma_kms(descriptor, lam, lookup_lam=None)[source]#

The same width expressed as a velocity dispersion.

Velocity widths are frame-invariant, so this is the currency in which the data and the library are compared and in which every reported number is quoted.

brainsp.instrumental_lsf.read_library_headers(ssp_folder, bases_info)[source]#

Read the resolution each template file states about itself.

Two header lines are understood, and a file may carry both:

# Spectral resolution: 2.51 (A) FWHM # smoothed by a vd (km/s) = 45.0

The first is a full width at half maximum in Angstrom, constant with wavelength. The second is a velocity dispersion applied on top of it, and is constant in km/s. A file carrying both has been broadened twice, so the two add in quadrature.

A file that states neither is returned as None. It is not guessed at: a library’s resolution is a measurable property of the library, and inventing a plausible number for it would produce exactly the kind of fit that looks right and is not. The caller is expected to say so and to name the library_resolution setting.

Returns:
list

One descriptor (or None) per entry in bases_info, in the same order.

brainsp.instrumental_lsf.gaussian_filter1d(values, sigma_pixels)[source]#

Convolve along the first axis with a Gaussian whose dispersion varies pixel by pixel, exactly, including for widths well below one pixel.

Sub-pixel is the ordinary case here, not an edge case: a 2.51 A library against a 2.9 A spectrograph asks for 1.45 A of extra width, which is a third of a pixel where the BC03 grid opens out to 4 A. A kernel built by point-sampling a Gaussian at integer offsets and renormalising cannot deliver that, and neither can one built by integrating it over the pixel: the first collapses below about 0.7 pixels and reaches zero near 0.1, and the second converges to the pixel’s own top hat, delivering a variance wrong by dlam^2/12 in one direction or the other at every width. Either way the broadening that was asked for is silently not the one applied, and the difference lands on the fitted stellar dispersion.

The construction here works in Fourier space, where a Gaussian of any width, undersampled or not, is the exact multiplier exp(-sigma^2 k^2 / 2). One transform cannot serve a width that changes with wavelength, so a set of sigma nodes is laid across the range of widths required, the whole array is convolved at each node, and every output pixel is a blend of the two nodes that bracket its own width.

The blend is linear in VARIANCE, not in sigma. A mixture of two Gaussians has the weighted mean of their variances as its second moment, so weights f and 1 - f chosen from sigma^2 make the delivered second moment equal to the requested one exactly, at every pixel, at every width. Blending linearly in sigma would instead deliver a variance too large by f (1 - f) (sigma_1 - sigma_0)^2, which is a fraction of a per cent at a pixel of width but a factor of two at a twentieth of one.

Nodes are spaced NODE_SPACING_PIXELS apart so the residual difference in SHAPE between the mixture and a true Gaussian stays negligible, and the count is capped at MAX_NODES. Only one node’s transform exists at a time, so the working set stays at the size of the input.

The array is zero-padded on both sides by more than the widest kernel before the transform, so the periodic wrap-around an FFT convolution implies cannot reach any pixel of the input. Zero padding also darkens the ends, which is deliberate: the caller divides by this function applied to an array of ones, and that ratio renormalises the ends in one step.

Parameters:
valuesarray, (n_pix,) or (n_pix, n_column)

Spectra to convolve.

sigma_pixels1D array, (n_pix,)

Gaussian dispersion at each pixel, in pixels of this grid.

brainsp.instrumental_lsf.convolve_on_native_grid(lam, block, sigma_lam)[source]#

Convolve templates at the sampling the library wrote them on.

The width that separates two line-spread functions is quoted in Angstrom on the template’s own wavelength axis, so that is where it belongs. The return value carries the axis it was computed on, because for one class of library grid that axis cannot be the native one.

Three grids, three answers:

Uniform in wavelength – the shipped BasesGM, a clean 1 A step – and uniform in log wavelength are both handled on the native axis itself, with the requested width converted to pixels of that axis. Nothing is interpolated and nothing is moved.

Everything else has no uniform sampling for the Fourier kernel to be exact on. BC03 is the example that matters: 1 A through the blue, opening out to 2, 3, 5 and eventually 2e5 A in the infrared. Those are convolved on a uniform log-wavelength axis whose velocity step is the FINEST the native grid uses anywhere in its range, so the working axis never undersamples what the file contains, and the caller resamples from that axis instead of from the native one. That is one flux-conserving mapping onto a grid at least as fine as the input, which is a different thing from convolving on the coarse grid the fit runs on.

The ends are renormalised rather than darkened: gaussian_filter1d zero-pads, so an array of ones convolved with the identical kernel is exactly the fraction of the kernel that landed inside the array, and dividing by it makes the operator preserve a constant end to end.

Returns:
axis1D array

The wavelengths the convolved block belongs to.

convolved2D array

One column per input column.

brainsp.instrumental_lsf.convolve_group_to_data_lsf(ssp_folder, bases_info, indices, lam_grid, i_ref, data_res, library_res, redshift)[source]#

Rebuild one resolution group from its files: convolve, resample, normalise.

This is the order the correction has to happen in. The kernel that carries a library up to a spectrograph’s line-spread function is a width in Angstrom on the grid the library was written on, so it is applied there, at the library’s own sampling, before anything has been interpolated. Only then is the result mapped onto the fitted log-lambda grid, and only then is it divided by its own value at the normalisation wavelength.

Doing it the other way round – resample, then convolve – applies the kernel on a grid whose Angstrom-per-pixel is not the one the width was quoted on, to flux that has already been through one interpolation, and it normalises before the operation that changes the number being normalised.

The columns are built from the files rather than from the matrix that is already on the log grid, because the native sampling is the whole point and it does not survive that matrix. Every column the caller replaces is therefore resampled exactly once; the first resampling is discarded, not composed with a second.

Each file is trimmed to the fitted range plus ten kernel dispersions before anything is convolved. The trim never cuts inside the fitted range, so which target pixels a template covers is exactly what it was, and the pixels it removes are ones the Gaussian tail reaches at the 1e-22 level. It matters for a library like BC03 that runs to 1.6e6 A: without it the working axis for a non-uniform grid would be laid across five decades of wavelength to serve a fit that uses one octave of it.

library_res is evaluated at rest wavelengths and data_res at lambda_rest * (1 + redshift), for the reason at the top of this module: the spectrograph smeared the light where it recorded it. Where the library is the broader of the two the difference is clipped to zero rather than sharpened. The caller has already refused any group for which that happens at a fitted pixel, so the clip can only bite outside the fitted window – on the BC03 infrared, say, where a library broadened in velocity overtakes an instrument of constant width in Angstrom.

Returns:
columns2D array, (n_grid, len(indices))

Normalised to exactly 1.0 at lam_grid[i_ref].

factors1D array, (len(indices),)

What each column was divided by. This is the column’s entry in fbase_norms: it is measured on the template that is actually fitted, because the convolution happened before it was measured.

usable1D bool array, (len(indices),)

False where the convolved column is zero or not finite at the normalisation wavelength and the 1.0 convention could not be restored.

delta_lam1D array

The broadening applied, in Angstrom, over the trimmed native grid of the first file in the group. Reported, not used.

brainsp.instrumental_lsf.prepare_templates(matrix, lam_grid, cfg, bases_info, fit_pixels=None, fbase_norms=None)[source]#

Bring the templates to the data’s line-spread function, or explain why not.

Called once, immediately after the templates have been mapped onto the log-lambda grid and after the pixels outside the template coverage have been dropped from the fit. The returned matrix has exactly the shape it came in with, so nothing downstream recompiles.

With instrumental_resolution unset there is nothing to match to, the matrix and the normalisation factors are returned as the very objects they came in as, and the fit is bit-for-bit what it was.

fit_pixels is the boolean mask of pixels the fit will actually use, which is where the comparison is made. Judging it over the whole grid instead binds the decision to pixels no template covers and that are about to be thrown away: on the reference setup, widening wavelength_max from 6900 to 9000 A flipped the module from correcting to refusing on the strength of 379 pixels beyond 8445 A that are identically zero in every template.

The decision is taken once per resolution group, not once for the library. A heterogeneous library is the normal case — the shipped one is 56 files at 2.51 A FWHM and 28 at 0.3 A FWHM plus 45 km/s — and a global refusal lets one group that crosses the data’s line-spread function leave every other group uncorrected. Groups whose difference is real at every fitted pixel are convolved; the rest are left at their native resolution; which is which is recorded, reported, and carried into dispersion_report.

A group that is corrected is rebuilt from its files by convolve_group_to_data_lsf: convolved at the library’s own sampling, then resampled onto lam_grid, then divided by its own value at the normalisation wavelength. The 1.0 at that wavelength and the matching entry in fbase_norms therefore hold by construction rather than by a correction applied afterwards — the factor is measured on the template that is actually fitted, because the convolution has already happened when it is measured. Everything downstream — the light fractions, Mini, Mcor, Q(H) — is written against that convention, and the physical SSP the column and its factor jointly describe is untouched.

fbase_norms may be None, in which case the returned array carries 1.0 for every group that was left alone and the measured factor for every group that was rebuilt.

Pixels that were exactly zero before the correction are zero after it: a template covers the span its file covers, convolving does not change that span, and resample_template leaves everything outside it at zero. The pixels at the edge of that span are renormalised rather than darkened; see convolve_native_gaussian.

Returns:
matrix2D array

Corrected templates, or the input array itself when no correction was applied.

fbase_norms1D array

Normalisation factors, matching the columns that came back.

infodict

Everything the summary needs, including the per-pixel dispersions and the per-group verdicts that survive into the reported numbers.

brainsp.instrumental_lsf.on_bound(value, lower, upper=None)[source]#

Is a fitted dispersion sitting on the lower or the upper end of its range?

Returns (on_lower, on_upper). A parameter at a bound is not a measurement of anything, and the stellar and the gas dispersions have to agree on when that has happened, so the test lives here once rather than in each of the two reports.

The test is made to a tolerance of 1e-4 of the WIDTH of the allowed range rather than to an absolute one in km/s, because a range starting at 0 makes any absolute tolerance either meaningless or arbitrary: the optimiser returns values like 5.6e-05 km/s on a railed fit, which an absolute 1e-6 km/s test misses and then reports as a measurement of 0.00. A range of zero width – the case where no upper bound was supplied – falls back to a relative test on the bound itself.

A non-finite value is on neither bound; it is a failed fit, and the caller has to say so in its own words.

brainsp.instrumental_lsf.instrumental_dispersion_at(info, wavelengths)[source]#

The instrumental dispersion in km/s at a set of wavelengths, or None.

info[“sigma_inst_kms”] is the data’s line-spread function expressed as a velocity dispersion, sampled on info[“lam”], which is the REST grid the fit runs on; the observed-frame lookup and the (1 + z) that cancels in km/s are already inside it. Interpolating it onto the rest wavelengths of a set of emission lines is therefore the whole of the operation, and it is written here rather than at the call site so that nothing else has to know which frame that array is indexed in.

None when instrumental_resolution was not set, which is the state in which BRAIN knows nothing about the instrument and says so rather than guessing.

brainsp.instrumental_lsf.dispersion_report(info, sigma_obs, weights_star, model_flux, good, lower_bound, upper_bound=None, reference_wavelength=5500.0)[source]#

Turn the fitted dispersion into the three numbers that belong in a summary.

sigma_obs

What the kinematic kernel actually applied to the library. This is the
number BRAIN has always reported as vd_min. On its own it is a
statement about the templates, not about the galaxy.

delta_sigma_inst

The signed quadrature difference between the data's line-spread
function and the library's, as the library entered the fit, averaged
over the fitted window. Positive means the data is the broader of the
two. A group of templates that was pre-convolved contributes zero,
because the library was brought to the data's line-spread function
before the fit ever saw it and the correction is not counted twice; a
group that was refused contributes sigma_inst^2 - sigma_lib^2, which is
what is still there.

Westfall et al. 2019 (AJ 158, 231) Eq. 6 is the quadrature relation
this rests on, sigma_obs^2 = sigma_star^2 + delta_sigma_inst^2, and
Eq. 7 averages it over the fitted channels. That average is an
unweighted mean, 1/N_fit, and the paper names uniform weighting as its
simplifying assumption. The weighting used here — by the model flux,
and by each template group's share of the light — is BRAIN's own
choice, on the grounds that a pixel with no light in it carries no
information about the line-spread function the fit saw. It was checked
against the unweighted mean and moves the answer by 0.4%.

sigma_star

sign(x) * sqrt(abs(x)) with x = sigma_obs^2 - delta_sigma_inst^2, where
the subtracted quantity keeps the sign of the variance difference. A
negative x means the fit applied less broadening than the difference in
line-spread functions alone demands, which no astrophysical dispersion
can produce; the magnitude is then an upper limit, not a measurement.

Both are reported as unknown, never as a number, when any template in the fit states no resolution. A number averaged over the subset that does state one is not a property of the fit that was run, and publishing it would contradict the log line that says no correction was applied. A power law or other featureless component is not a template of unknown resolution and does not trigger this; see _is_featureless.

An upper limit is also reported whenever sigma_obs comes back sitting on the lower bound of its allowed range, because a parameter at a bound is not a measurement of anything. See on_bound for the test.
