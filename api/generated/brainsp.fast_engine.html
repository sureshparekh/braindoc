brainsp.fast_engine#

NewBrain Fast Engine — unified 100% JAX forward model for all three photoionization modes.

Replaces two things at once:

1. The scipy fallback that `nepop` and `photopop` modes used. The nebular
   fixed point is now a `lax.fori_loop` with a constant trip count, so the
   whole residual is traceable and the pure-JAX LM drives every mode.

2. The redundant work in the `spop`-mode forward model. `rfft(M_star)` is
   hoisted out of the fit (M_star never changes), and the Jacobian only
   re-broadens for the two parameters that can actually alter the stellar
   broadening.

The parameter vector is unchanged:

[Av, YAV, sigma_star, v0_star, sig_g0, v0_g0, sig_g1, v0_g1, ...]

Modes:

"spop"     - stellar populations alone; emission lines are not fitted.
"nepop"    - nebular continuum carried as a free NNLS column, its amplitude
              read back as Q_eff. Emission lines stay free and empirical.
              The nebular light enters the model ONCE, through that column;
              it is not also subtracted from the data.
"photopop" - as nepop, plus hydrogen line amplitudes tied to the Case B
              prediction from the same Q(H) via augmented-NNLS penalty rows.

brainsp.fast_engine.build_constants(M_star, lam, flux, inv_sigma, velscale, dk, D_full, yav_flags, line_table, mode='spop', qh_ratios=None, neb_template=None, k_norm=0.0, av_neb=0.0, f_capture=1.0, H_gas_idx=None, H_ratios=None, H_dk=None, C_Hbeta=0.0, sc_weight=1000.0, sc_damping=1.0, n_neb_iter=12, v0_max=5000.0, sigma_max=500.0, solver='active_set', simplex=False, fit_lines=None)[source]#

Precompute every constant the forward model needs.

On simplex: the constraint is sum(x_j) + y = 1, but the normalisation flux F_lambda0 is itself a fitted parameter bounded to [0.5, 1.5] times the measured value (fnormlow / fnormupp), so the equality pins the fractions while F_lambda0 absorbs the overall scale. That is equivalent to leaving the weights free with sum(w) inside [0.5, 1.5] — which is what BRAIN does, and its sum lands at ~1.07. Imposing a hard sum(x)=1 instead is a different, stricter condition: measured on the reference spectrum it costs chi2 (1843 -> 1992), pushes Av from 0.24 to 0.73 and pins sigma_star at its lower bound. So it defaults off. The reported light fractions are normalised to 100% regardless, as they always were.

The stellar templates are edge-padded at both ends before their transform is taken, so the broadening is a linear convolution and not a periodic one. v0_max and sigma_max set how far it has to reach; see _kinematic_reach, which also says what happens if a caller widens the fitted bounds past them.

brainsp.fast_engine.broaden(C, sigma_v, v0, n_pad, n_pix, n_left)[source]#

Broaden + shift all stellar templates.

rfft(M_star) is supplied precomputed in C.M_fft, so this is a kernel multiply plus one inverse transform — the single biggest saving in the whole forward model.

C.M_fft is the transform of the EDGE-PADDED matrix, n_left pixels of it before the first fitted pixel, so the window comes back out of the middle of the result and not off its front. Slicing from 0 instead would return a spectrum shifted by n_left pixels, which at 129 pixels and 58 km/s is 7500 km/s and would be anything but subtle; slicing from n_left + 1 would be one pixel, which would not.

brainsp.fast_engine.forward_from_broad(C, params, M_broad, S, Q_init=0.0, P_init=None)[source]#

Full forward model given an already-broadened stellar matrix.

Returns (residual, weights, Q_eff, M_full, P_out).

The nebular continuum enters exactly once, and the two modes put it in different places. In “nepop” it is a column of M_full (built in _design when S.n_neb is 1) and the NNLS fits its amplitude, so the residual is formed against the untouched data. In “photopop” there is no such column – S.n_neb is 0 – and the nebular is instead subtracted from the data at the Q(H) the fixed point has reached. Subtracting in nepop mode as well minimised flux - stellar - gas - 2*(nebular), which is chi2 plus a shrinkage penalty ||nebular amplitude||^2 that the inner NNLS never sees; the outer LM could only satisfy it by driving A_V, sigma and v0 to where the NNLS wanted less nebular.

This is the function the Jacobian calls for the six parameters that cannot change the stellar broadening (Av, YAV, and every gas kinematic), which is where the speedup comes from: no FFT at all on this path.

Q_init warm-starts the nebular fixed point. With Q_init = 0 the loop reproduces the original cold-start behaviour; the Jacobian passes the converged Q* from the centre point so a single extra iteration suffices.

In photopop mode the loop runs a FIXED S.n_neb_iter passes, undamped, and returns the Q it actually built the residual with – not the Q the last pass would have gone on to use. Those differ by a factor of about two when the loop is truncated, and everything downstream (tau, the nebular spectrum, f_neb, the Nebular_Fit column) wants the one that is physically in the model.

On the trip count: the first pass starts from Q = 0, which deactivates the SC penalty rows entirely, so it overshoots the fixed point by ~144x. Averaging that iterate into every subsequent step, which is what sc_damping < 1 does, is what made the sequence non-monotone and slow – abs(dQ)/Q < 1e-10 took a median of 44 iterations at damping 0.5 against 7 undamped, over 25 parameter draws spanning the whole bounds box. Undamped with 12 passes the fixed point is reached everywhere tested, and the trip count is fixed, so the Jacobian runs the identical schedule to the residual by construction rather than by argument.

brainsp.fast_engine.jacobian(C, params, S, n_par, central=True, diff_step=0.001)[source]#

Central (or forward) differences, exploiting two pieces of structure.

  1. Only params 2 and 3 (sigma_star, v0_star) alter M_broad. The remaining

n_par - 2 parameters reuse the centre point's broadened matrix, so of
the 2*n_par+1 evaluations only 4 pay for an inverse FFT.

  1. The nebular fixed point runs the SAME number of iterations from the

SAME cold start (Q = 0) as the residual the LM is minimising.

This matters more than it looks. An earlier version converged Q* once
at the centre and warm-started each perturbation with a single extra
iteration — 1.5x faster, and wrong. The Jacobian then described a
different map than `residual_only`, so the predicted reduction never
matched the actual one, the gain ratio went to noise, and every LM step
was rejected: `photopop` mode terminated at its initial guess. Keep the two
maps identical; the fixed point is cheap now that the Gram matrix is
hoisted out of the loop.

  1. The centre point’s passive set P0 is reused as the warm start for every

perturbed linear solve. That is exact — solve_active_set purges an
illegal inherited set before it starts, so it reaches the same vertex
wherever it starts. Measured max|J_warm - J_cold| = 0 exactly in all
three modes, and it is cheaper in two of them (nepop Jacobian
91 ms against 125 ms cold). Before the purge existed this warm start
was NOT exact and inflated the photopop-mode A_V column by 19x.
brainsp.fast_engine.lm_optimize(C, x0, bounds_lo, bounds_hi, S, n_par, max_iter=200, ftol=1e-05, xtol=1e-05, diff_step=0.001, central=True)[source]#

Projected Levenberg-Marquardt, identical in structure and convergence logic to optimizer._lm_optimize, but driving the unified forward model so it serves all three photoionization modes.

max_iter is a TRACED runtime value, not a static one — it only bounds a lax.while_loop, so it need not be baked into the compiled kernel. Together with the bounds, tolerances, starting point, reddening curve and regularisation strength (all already runtime arrays), this means the entire tunable surface of a fit can change without recompiling. Verified: max_iter 200 -> 150 -> 300 reuses the cached kernel and returns identical results. Only the problem’s shape forces a rebuild — pixel count, template count, regularisation order, photoionization mode.

On the stagnation rule. n_stag counts consecutive iterations whose chi2 moved by less than ftol*100, and five of them end the fit as converged. It advances only on ACCEPTED steps. A rejected trial leaves chi2 exactly where it was, so counting rejections as stagnation turned the rule into a five-rejection kill switch wearing a convergence label — and a rejection is precisely the event LM answers by raising lambda, which is the recovery mechanism, not a sign of convergence. Measured: a nepop fit took ten accepted steps still improving at 2.2e-3 per iteration, hit five rejections while lambda climbed from 5.1e-8 to 4.1e-6, and returned “converged” having thrown away 0.12 in chi2 and 18% of A_V. Rejections are already bounded by the n_rej < 10 test in cond, which is the honest place for that limit and which now also reports convergence rather than “max iter”.

step_norm is measured against the width of the bounds box, not against abs(x). Against abs(x) it is scale-broken: sigma_star converges onto its lower bound of zero and yav is pinned at zero, so the denominator collapses to 1e-10 and step_norm reads 1e7 or more, which made the classical test unreachable and left xtol with no effect at all.

brainsp.fast_engine.grid_chi2(C, v0_grid, sigma_star_init, av_init, sigma_gas_init, S, n_groups)[source]#

chi2 across a velocity grid, vmapped.

Deliberately evaluated in “spop” mode regardless of the requested mode: this only picks the velocity basin for the LM, the weights are discarded, and adding the nebular fixed point here would cost 4x for no benefit. This matches the existing behaviour of SpectralFitter.grid_search_v0.
