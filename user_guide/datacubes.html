Datacubes#

A datacube run is an ordered chain of preparation stages followed by the fit, over one or more cubes. Each cube is opened once, every stage adds the extensions it produces, and the result is written as a megacube: the cube you gave BRAIN with the fit added to it (<output_dir>/<name>-BRAIN_MEGACUBE.fits).

The arrangement and the extension names are those of the MaNGA megacubes of Riffel et al. (2023), so tools written for those megacubes read BRAIN’s unchanged. Please cite that paper when you use BRAIN’s megacubes (Citing BRAIN).

From Python#

import brainsp

pipeline = brainsp.CubePipeline(
    "manga-8626-12704-LOGCUBE.fits",
    redshift=0.04724,                          # required: the galaxy's z
    settings=brainsp.Settings(nebular_mode="espop"),
    wavelength_scale="vacuum",                 # required in line modes
    galactic_ebv=0.03,                         # Milky Way dust, removed first
    sn_mask=[3, 5, 10], fit_sn_threshold=3,    # fit spaxels with S/N > 3
    wavelength_mask="emission_lines.sm",   # applied to every spaxel
    output_dir="megacubes")
pipeline.validate()          # every problem, before reading a spaxel
written = pipeline.run(device="gpu")
cube = brainsp.read_megacube(written[0])

brainsp.fit_cube() is the short form for one cube; it returns the opened megacube. pipeline.export_script("run.py") writes the whole run as one Python file.

From the command line:

brainsp cube manga-8626-12704-LOGCUBE.fits --redshift 0.04724 \
    --wavelength-scale vacuum --ebv 0.03 --sn 3 5 10 --fit-sn 3 \
    --mask emission_lines.sm --set nebular_mode=espop -o megacubes

In the interface: the Datacube workspace (The Datacube workspace).

The stages, in order#

Every stage but the fit is off until asked for: each one changes the data, and a stage that ran because it was a default is one nobody decided to run.

removes \(E(B-V)\) of Milky Way dust at the observed wavelengths (Pre-fit corrections); records DRD_LAW, DRD_EBV, DRD_RV

a 2-D low-pass filter over the field at each wavelength ; spreads each spaxel over about six neighbours, records the flux kept in BW_KEPT

Each stage is handed the extension the previous one wrote, so the names never have to be threaded by hand.

Signal-to-noise masks#

sn_mask computes the S/N of every spaxel over a rest-frame window (4000–6000 Å by default) with one of five estimators (method):

Method

S/N

ivar (default)

mean of \(F\sqrt{\rm IVAR}\) over the window: what the fit itself sees

ivar_median

median of the same

variance

mean of \(F/\sqrt{\rm VAR}\)

error

mean of \(F/\sigma\)

mean_std

mean / standard deviation of the flux over the window

and writes SN_MASKS_<t>, 1 where the spaxel is above \(t\), for each threshold. fit_sn_threshold=t then fits only those spaxels; the others are left unfitted (blank in every map). The interface previews each threshold on the map before anything runs.

The wavelength mask#

One mask, applied to every spaxel’s fit, in the rest frame: a file (.sm/.gm or a list) or regions [(start, end, weight), ...] (Masks and weights). The interface builds it by dragging across any spaxel’s spectrum. It is written beside the outputs as brain_wavelength_mask.sm and recorded in the megacube.

Several cubes, each with its own values#

per_cube takes a CSV file or a list of dictionaries. The first column (or target) names the cube; every other column overrides one setting for that cube alone:

target,redshift,ebv,mask file
manga-8241-12705-LOGCUBE.fits,0.0281,0.0296,
manga-8566-1901-LOGCUBE.fits,0.0882,0.0231,masks/8566.sm

brainsp.CubePipeline(per_cube="targets.csv", settings=s, ...)

brainsp cube cubes/*.fits --table targets.csv ...

The columns accepted are those the enabled stages read: redshift, ebv, rv, law, mask file, thresholds, sn window, batch size, resample size, wavelength scale. A column no enabled stage reads is refused before the run starts, with the accepted ones listed, rather than ignored.

What the fit does to each spaxel#

Exactly what a single spectrum’s fit does: the same model, solver and settings, run on many spaxels at once (Theory). A spaxel of a cube and the same spectrum fitted on its own give the same answer (the test suite checks it). The differences are in what is written: maps instead of a summary file, and observed emission-line fluxes in the cube’s own units (the megacube convention) instead of the normalised, extinction-corrected ones a spectrum’s summary holds (Output files).

On a GPU, spaxels are fitted in batches sized to the card’s memory; on a CPU, by worker processes, one per core (Speed, GPUs and CPUs). The result is the same either way to rounding.

What validate() refuses#

Everything that can be refused before a spaxel is read: no cube, a cube that is not there, no stage enabled, a fit asked to use an S/N threshold the S/N stage does not compute, an uncertainty declared to be a flux, an invalid settings, a missing wavelength scale in a line mode, the resolution stage together with instrumental_resolution, overlapping population bins, a per-cube column nothing reads, and a missing redshift. Every problem is listed at once, each with the stage it belongs to; the interface marks each in its own panel.
