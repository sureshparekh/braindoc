What a fit writes#

A spectrum’s fit writes a few small text files; a datacube’s fit writes one FITS file, the megacube. Both can be read back into Python with one call, and both open in the interface.

A spectrum#

Every spectrum’s fit writes, to the output folder (brain_out by default), files named after the spectrum:

File

What it holds

<name>_summary.txt

every fitted and derived quantity, the population vector, the gas kinematics, the 1σ uncertainties and the emission lines

<name>_fitted.txt

the observed spectrum and the model, column by column: wavelength, observed flux, total model, stellar model, emission-line model, error, residual (and the nebular continuum in nespop)

<name>_settings.txt

every setting the fit used and the templates it used, so that the fit can be repeated

<name>_fit.pdf

the standard figure, when make_plot is on

The summary is plain text, one value per line followed by its name in square brackets, so it can be read by eye, by any program, or by BRAIN:

   31.93                                  [v0_min  (km/s)]
   63.24                                  [vd_min  (km/s), OBSERVED]
 0.3304                                   [AV_min  (mag)]
  5.73937E-02                             [err AV_min (mag)]

r = brainsp.read_result("brain_out/galaxy_summary.txt")
r.av, r.av_err, r.sigma_star, r.lines["Halpha_6563"]

Spectrum output files explains every line of both files, and Reading a spectrum’s results every attribute of the result.

Note

Every dispersion in the summary states its convention. vd_min and sigma_obs are observed: the instrument is still in them. sigma_star is intrinsic: the difference between the instrumental and the library resolution has been taken out. sigma_gas is intrinsic as well, because the emission-line model includes the instrument. Where the library’s resolution is unknown, sigma_star reads unknown rather than a guess.

A datacube#

A datacube’s fit writes one FITS file, <cube>-BRAIN_MEGACUBE.fits, to the output folder (brain_ifu_out by default). It keeps the input cube and adds, for every fitted spaxel:

Extensions

Content

FLXOBS, FLXSYN, STELLAR, MODEL, NEBULAR

the observed spectrum and the model with its components, on a common wavelength grid

PoPBins

the maps: light and mass fractions of age bins, mean ages and metallicities, \(A_V\), kinematics, fit quality, masses and star formation rates

PoPVecsL, PoPVecsM, PoPVecsMini

the full population vectors, in light, present mass and initial mass

KINEMATICS

the stellar and gas kinematics

FLUX_M, EQW_M, SOLUTION, …

every emission line’s flux, equivalent width, velocity and dispersion

NEBMAPS

the nebular quantities (nespop)

<EXT>_ERR

the 1σ error of each of these, plane for plane

SN_MASKS_*, SNMAP

the signal-to-noise masks and map the fit used

BRAINCFG, FITCONFIG

the settings, so that the file records how it was made

Read it in Python with brainsp.read_megacube():

cube = brainsp.read_megacube("brain_ifu_out/manga-BRAIN_MEGACUBE.fits")
cube.groups.keys()           # Populations, Kinematics, Emission lines, ...
cube.plane("vrot_star")      # one map, NaN where no spaxel was fitted
cube.plane("Sigma_star error")
cube.spectrum(20, 21)        # the observed and model spectra of one spaxel

or open it in the interface’s Results workspace (Exploring a megacube). Megacube files describes every extension and plane.

The uncertainties#

Every quantity above has a 1σ uncertainty, written beside it: in the summary’s ## Uncertainties (1 sigma) ## section and in the table of emission lines for a spectrum, and in the <EXT>_ERR extensions for a datacube. An uncertainty BRAIN cannot calibrate is written as NaN, never as a number known to be wrong. Uncertainties explains the two methods and which quantities each covers.
