Your data#

BRAIN reads spectra as plain text files and datacubes as FITS files. This page gives the exact format of each, and what BRAIN does with pixels that have no error or are flagged as bad.

A spectrum#

One pixel per line, in two to four columns separated by spaces:

# wavelength   flux        error       flag
3541.0000      0.695938    1.229688    0
3541.6980      0.712344    1.221907    0
3542.3963      0.698112    1.230114    1

Column

Content

Required

1

wavelength, in Å

yes

2

flux density, in any consistent unit

yes

3

the flux’s 1σ uncertainty, in the same unit

no, but strongly recommended

4

a quality flag: 0 for a good pixel, anything else for a bad one

no

Lines starting with # are comments. The wavelengths may be spaced linearly, logarithmically or irregularly: BRAIN fits the spectrum on its own pixels and never resamples it.

Warning

A flag of 0 means good. A pipeline that writes 1 for good pixels must have its flag column inverted first, otherwise every pixel is rejected and the fit stops, reporting that no pixel can be fitted.

Pixels without an error. A pixel whose error is zero, negative or not a number is left out of the fit (missing_error: exclude, the default). With missing_error: interpolate it is kept, with an error interpolated from its neighbours; its flux is never changed.

No error column at all. Every pixel then counts the same, and \(\chi^2\) is no longer in units of the noise. Set has_errorbars: false so that BRAIN does not read it as calibrated. The formal uncertainties assume real errors, so for such a spectrum use the bootstrap instead (Uncertainties).

Rest frame or observed frame. By default BRAIN takes the spectrum to be in the rest frame. If it is still in the observed frame, set spectrum_in_rest_frame: false and give its spectrum_redshift; BRAIN divides the wavelengths by \(1+z\) itself. In both cases give the redshift you removed, because the instrument smeared the light at the observed wavelength (Corrections before the fit).

From Python, arrays work as well as files. They are written to the output folder first, so that the result always names a file:

import brainsp
r = brainsp.fit_spectrum((wavelength, flux, error), name="my_galaxy")

A datacube#

A FITS file holding the flux as a three-dimensional image (wavelength, y, x) in one extension, its uncertainty in another, and optionally a quality mask in a third. The extension names are settings, so any layout works; the usual ones are:

MaNGA (LOGCUBE)

MUSE

CALIFA

flux

FLUX

DATA

PRIMARY

uncertainty

IVAR (inverse variance)

STAT (variance)

ERROR (error)

quality mask

MASK

DQ (see the warning)

BADPIX (see the warning)

wavelength scale

vacuum

air

air

In Python these are flux_hdu, error_hdu, error_type ("inv_variance", "variance", "error" or "inv_error") and mask_hdu of CubePipeline; in the interface, the Input extensions of the Cubes step; on the command line, --flux-hdu, --error-hdu, --error-type and --mask-hdu.

Warning

The mask extension is read as MaNGA’s bitmask: a pixel is bad when bit 10 (DONOTUSE, value 1024) is set, and every other bit is ignored. A MUSE DQ or a CALIFA BADPIX plane marks bad pixels with other values, which would all be read as good. For those cubes, write a mask plane holding 1024 where a pixel is bad, or give no mask (mask_hdu=None) and let the uncertainty carry it: a pixel with zero inverse variance is never fitted.

The wavelength axis is read from a WAVE extension when there is one (MaNGA has one), and otherwise from the header keywords CRVAL3, CDELT3 or CD3_3, and CRPIX3, with a logarithmic axis when CTYPE3 ends in -LOG. The celestial coordinates of the first two axes are carried into every map BRAIN exports.

The redshift is not read from the file. Give it with redshift= (Python), --redshift (command line) or the Corrections step (interface), or one per cube in a table when you fit several.

The instrumental resolution matters for every dispersion BRAIN reports. A MaNGA cube’s own line-spread function (the PRESPECRES extension) is read automatically; for other cubes give instrumental_resolution (Emission lines and resolution).
