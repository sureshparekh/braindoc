On a server or a cluster#

Nothing in a fit needs a display, so BRAIN runs as it is on a remote server, in a batch job or on a cluster node: through Python scripts, the brainsp command, or a run exported from the interface. This tutorial shows the usual patterns.

The Python version as one file, ready to run, and the SLURM job: 08_many_cubes.py, brain_job.slurm.

The simplest: an exported run#

Set the run up in the interface on your own computer, press Export run script… and save the script in the folder that holds the data. Copy the folder to the server and run it there:

rsync -av my_project/ server:my_project/
ssh server
cd my_project
python run_brain_ifu.py --check      # validate on the server's paths
python run_brain_ifu.py --device gpu

Paths inside the folder are relative to the script, so they hold on the server (A run as one file).

A SLURM job#

#!/bin/bash
#SBATCH --job-name=brain
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=16
#SBATCH --time=04:00:00

source ~/miniconda3/bin/activate brain
brainsp cube cubes/*.fits --table targets.csv --wavelength-scale vacuum \
    --sn 3 10 --fit-sn 3 --set nebular_mode=espop --device gpu -o megacubes

BRAIN uses what SLURM gives it, not the whole node: the cores of --cpus-per-task (minus two), and the GPUs of --gres. With several GPUs in the allocation, the cubes are dealt out to them, one process per GPU (Many datacubes).

Many cubes over many nodes#

A campaign larger than one node is split with an array job, each task fitting its share:

#!/bin/bash
#SBATCH --array=0-9
#SBATCH --gres=gpu:1
#SBATCH --time=04:00:00
source ~/miniconda3/bin/activate brain
ls cubes/*.fits | awk "NR % 10 == $SLURM_ARRAY_TASK_ID" > part_$SLURM_ARRAY_TASK_ID.txt
brainsp cube $(cat part_$SLURM_ARRAY_TASK_ID.txt) --redshift 0.03 \
    --wavelength-scale vacuum --sn 3 --fit-sn 3 -o megacubes

Every task writes to the same output folder, one megacube per cube. Rerun a stopped campaign with the same command: the Python keyword overwrite=False (or unticking Re-run a cube whose megacube already exists in an exported run) skips the cubes already done.

On a CPU-only server#

A server without a GPU is used through BRAIN’s CPU workers, one per physical core and never more than all but two of the cores the job may use. On a 32-core workstation, a 180-spaxel datacube in espop took 89 s on the CPU, against 90 s on an RTX 3060 (CPUs and GPUs). Ask SLURM for whole cores (--cpus-per-task) rather than hyperthreads.

In Python, without the command line#

import brainsp
brainsp.set_device("gpu")
p = brainsp.CubePipeline("cubes/*.fits", per_cube="targets.csv",
                         settings="my_settings.yaml", wavelength_scale="vacuum",
                         sn_mask=[3], fit_sn_threshold=3, output_dir="megacubes",
                         overwrite=False)
p.validate()
p.run(log=print)

The compiled-code cache#

The first fit of a problem size compiles; later runs load the compiled code from ~/.cache/brain/jax in about half a second. On a cluster whose home folder is shared between nodes, the cache is shared too, so only the first job compiles. Point BRAIN_CACHE_DIR at a shared scratch folder if the home folder is small.
